# v0.21.0 (2026-11-18)

A Threshold monitor can run a SQL query in place of a Query. Dashboards get Text blocks in Markdown, threshold lines on line and area Charts, and filters that open on saved default values. A Chart with several columns of one unit draws them over one axis, with a hue for each column. A Dashboard card no longer scrolls inside. It's still a 0.x prototype, not yet hardened for production.

## Added

- **SQL Monitors.** A Threshold monitor can run a [SQL query](../logs/sql.md) in place of a Query, on installs where SQL queries are on. Use it for a join, a subquery, a window, or a read of the `events` or `spans` tables. On the Monitor form, a Threshold monitor gets the **Builder | Query | SQL** switch, and SQL opens with the readable SQL of the Query. Saving runs the SQL once, and refuses SQL that fails or a table without one number column. A SQL Monitor can compare the change: it reads its SQL again over the Baseline range. Each read stops after 10 s. The preview lists the groups a run now would find, with no chart. Over MCP, `create_monitor` and `update_monitor` take `sql` in place of `query`, and `run_monitor` with `preview: true` shows what a run would find without saving. While SQL queries are off, a SQL Monitor's runs fail with the reason, and its form shows the SQL read-only. [docs/logs/monitors.md](../logs/monitors.md) has it.
- **Text blocks on Dashboards.** **Add text**, beside Add chart and in a Section's menu, adds a block of Markdown with an optional title: notes, runbook steps, links. GitHub's Markdown works, with tables (and their column alignment), task lists and strikethrough. A Text block shows no raw HTML, shows an image as a link to its address, and opens links in a new tab. It runs no Query. Over MCP, `add_chart` and `update_chart` take `viz: "text"` with `text`, and `get_chart_data` says a Text block has no data. [ADR 0022](../adr/0022-text-blocks-are-dashboard-charts-of-viz-text.md) records why a Text block is a Chart of viz `text`.
- **Threshold lines.** A line or area Chart can have up to 5 threshold lines, each a value with an optional label and a severity, warn or critical. Each line is drawn across the plot, and the value axis always reaches it. The Chart editor sets them, and over MCP, `add_chart` and `update_chart` take `options.thresholds`. The Monitor form draws a Monitor's threshold with the same line.
- **Default values for Dashboard filters.** A filter can have default values in the Filters dialog, or with `create_dashboard` and `update_dashboard`. The page opens the filter on them when the URL has no value for it, and the URL keeps only the values a member picked, so a shared link follows a later change to the default. A member who sets the filter to All stays on All after a reload. `get_chart_data` runs a filter that the request does not give with its default values.

## Changed

- **A Chart with several columns of one unit draws them over one axis.** When a Dashboard Chart's unit is set, all its columns share that unit and one value axis, such as `received` and `processed` per second. When a by column splits two or more columns, each column gets a hue and each group a shade of it. The legend and the tooltip name the column, as `r4 · received`. Without a unit, the axes are chosen as before. The Logs explorer also gets the hue for each column.
- **A Dashboard card no longer scrolls inside.** The chart fills the card under its legend, however many lines the legend takes. The tooltip has more space between a row's name and its value.
- **After a first Passkey or Authenticator app,** Continue goes to Settings → User inside the Organization, with its sidebar.

## Fixed

- **Changing the hours on local disk no longer logs a failure on a large install.** ClickHouse's `ALTER ... MODIFY TTL` waited for the TTL to apply to every part, which took longer than 30 s with Logs in the bucket. The change was applied, but the log said it failed. EventStore now returns once the TTL is set, and ClickHouse applies it in the background, as before.

## Upgrading from v0.20.0

`deploy/install` runs Console's 2 migrations. They need no data step:

- Monitors get a `language`, `query` for every saved Monitor.
- Dashboard Charts get a `text`, and a Chart's Project, Query and title can be empty, for Text blocks.

`deploy/` has no change. A filter has no default values until you set them, so every Dashboard opens as before.

```bash
git fetch --tags && git checkout v0.21.0 && deploy/install
```
