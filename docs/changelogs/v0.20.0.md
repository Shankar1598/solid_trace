# v0.20.0 (2026-11-17)

MCP clients sign in through the browser with OAuth, so you copy no secret into them. Users can turn on Two-factor, with an Authenticator app or a Passkey, and an Organization can require it. Sessions now end, after 24 hours or after 7 days with Remember me. Dashboards get Sections that you can fold. Console's and ingest's URLs are settings on Settings → Instance. This release also fixes the known security defects in Console's and EventStore's dependencies. It's still a 0.x prototype, not yet hardened for production.

## Added

- **MCP clients sign in through the browser.** Add the server with only its URL, as `claude mcp add --transport http solidtrace https://<console>/mcp`, and sign in from the client. Console's approval page shows the client and the host it sends you back to. You sign in, with Two-factor where you have it, pick one Organization and approve. The client gets short-lived access tokens and refresh tokens that rotate. Each sign-in is for one Organization. Settings → User lists your **Signed-in clients**, and Revoke stops one at once. A machine with no browser signs in with the device flow. OAuth is on only where the Console URL is `https://`, or `http://` on loopback for development. [docs/mcp.md](../mcp.md#sign-in-through-the-browser) and [ADR 0021](../adr/0021-mcp-clients-sign-in-with-oauth-in-console.md) have it.
- **Two-factor.** A user adds an Authenticator app (a 6-digit code) or a **Passkey** on Settings → User. Once a user has one, a password alone no longer signs them in. The first factor gives 10 **Recovery codes**, shown once. A Passkey can also sign in alone. Passkeys are offered only where the Console URL is `https://` on a domain ([ADR 0018](../adr/0018-passkeys-count-as-two-factor-on-the-console-urls-domain.md)). A user who has lost every factor asks the operator, who runs `bin/rails users:reset_two_factor EMAIL=<email>` ([docs/install.md](../install.md)).
- **Require two-factor.** An Organization admin who has Two-factor can turn it on in the Organization's settings. Then a member with no Two-factor goes to the set-up page from the Organization's pages, and the Organization refuses that member's MCP calls. The member's other Organizations don't change. It is off by default.
- **Remember me** on the sign-in page.
- **Sections on Dashboards.** A Section is a titled row of Charts. Add, rename, move and delete Sections from the Dashboard page, and pick a Chart's Section in the Chart editor. A Chart can be in no Section: those Charts show at the top, as before. Each viewer can fold a Section to its header, and the browser keeps the fold. Deleting a Section keeps its Charts, in no Section. Over MCP: `add_section`, `update_section`, `delete_section`, and `section_id` on `add_chart` and `update_chart`. `get_dashboard` lists the Sections.
- **Console URL and Ingest URL** on Settings → Instance, and with `get_instance_settings` and `update_instance_settings` over MCP. Every email, Invite link, MCP URL, DSN and Logs snippet uses them, with no restart. Blank keeps `CONSOLE_URL` or `PUBLIC_INGEST_URL` from `deploy/.env` ([ADR 0017](../adr/0017-public-urls-are-instance-settings.md)).
- **A show-password button** (an eye) on the password fields of sign-in, sign-up, the Invite link, the password reset and the password proof.

## Changed

- **Sessions end.** A Session lasts 24 hours from sign-in, or 7 days with Remember me. Console refuses an expired Session itself.
- **A new Chart goes beside the last row** of its Section (or of no Section) when that row has space, and under it only when the row is full. Before, it always went under every Chart at the left. This applies to Add chart, Duplicate and `add_chart`. Charts already on a Dashboard don't move.
- **A firing Monitor's Slack message starts with 🚨**, not 🔥.
- **Console's image leaves out the test gems.**
- **SolidTrace is free software under the AGPL-3.0** ([LICENSE](../../LICENSE)).

## Upgrading from v0.19.0

`deploy/install` runs Console's 11 migrations. They need no data step:

- Sessions get an expiry. A Session signed in before the upgrade lasts 7 more days, so the upgrade doesn't sign everyone out.
- Charts get a Section that is empty, so every Dashboard looks as before.
- The other migrations add tables and columns for Two-factor, Passkeys, Recovery codes, OAuth and the URL settings.

API tokens don't change: MCP clients and scripts that send one keep working. The exception is an Organization whose admin turns on Require two-factor: it refuses the API token of a user who has no Two-factor. For browser sign-in, MCP clients need an `https://` Console URL. Settings → API tokens & MCP says why OAuth is off when it is.

```bash
git fetch --tags && git checkout v0.20.0 && deploy/install
```

Images, for `linux/amd64` and `linux/arm64`:

- `ghcr.io/shankar1598/solid-trace-console:v0.20.0`
- `ghcr.io/shankar1598/solid-trace-event-store:v0.20.0`
