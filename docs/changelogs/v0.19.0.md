# v0.19.0 (2026-11-05)

With a bucket, the disk limit no longer deletes a day when a move to the bucket fails; it waits for the move and logs an error. The hours Logs stay on local disk, and the threads ClickHouse reads Logs with, move to Settings → Instance, so an Instance admin changes them with no restart. It's still a 0.x prototype, not yet hardened for production.

## Fixed

- **With a bucket, the disk limit deletes no Logs.** Past the disk limit, EventStore moves the oldest days to the bucket. v0.18.0 then deleted the oldest days still on local disk if a move had failed, and that could be the day still being written. Now, with a bucket, it only moves days: if local disk is still past the limit, it logs "Enforcing the disk limit failed, retrying" and tries again a minute later. If the disk fills before the bucket answers, ClickHouse stores no more Logs, rather than losing a day. Without a bucket, the disk limit still deletes the oldest days. [docs/logs/object-store.md](../logs/object-store.md#when-the-bucket-is-down) has it.

## Added

- **Log read threads** (`logs_read_threads`) on Settings → Instance, and with `get_instance_settings` and `update_instance_settings` over MCP, from 0 to 64. It's ClickHouse's `max_threads` for every Log read: Queries, the Logs explorer's table, histogram and Fields, a Log by id, Match Monitors, traces and Transactions. SQL queries, inserts, merges and cleanup keep their own. The default, 0, sets none, so ClickHouse uses one per CPU core, as before. More threads fetch more of a cold read from the bucket at once. A change applies from the next read.

## Changed

- **The hours on local disk are an instance setting.** How long Logs stay on ClickHouse's local disk before they move to the bucket (`local_cache_hours`, "Hours on local disk", 0 to 720, 24 by default) is set on Settings → Instance, or with `update_instance_settings` over MCP. EventStore reads it every minute and changes the Logs and Spans tables' TTL when it changes, with no restart. Saving a change on the page first asks you to confirm, with the old and new hours: older Logs are read from the slower bucket, a higher value counts toward the disk limit and doesn't bring moved Logs back, and ClickHouse works out every part's move time again. The field is disabled without a bucket. v0.18.0 read it from `event_store.yml`, which took an EventStore restart to change. [docs/logs/object-store.md](../logs/object-store.md#changing-the-hours-on-local-disk) has it.
- **Caddy 2.11.8**, fixing 8 of Caddy 2.11.7's 9 image findings.

## Upgrading from v0.18.0

`deploy/install` runs Console's two migrations: `instance_settings` gains `logs_read_threads`, 0, and `local_cache_hours`, 24, for every install. If your `config/event_store.yml` sets `object_store.local_cache_hours`, EventStore now ignores it and warns at start. Set the same value on Settings → Instance after the install if it isn't 24, then remove the key.

```bash
git fetch --tags && git checkout v0.19.0 && deploy/install
```
