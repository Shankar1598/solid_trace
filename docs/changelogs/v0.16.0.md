# v0.16.0 (2026-10-29)

Adds % change to Threshold monitors: a Monitor can fire when a group's number rises, falls or changes by a percent from its Baseline, instead of when the number itself passes a threshold. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Comparing the change.** A Threshold monitor's Compare setting is "The value" (as before) or "The change". Comparing the change, it fires when the number rises, falls or changes by at least a percent from its **Baseline**: the same Query over the range just before, the same range 1 day earlier, or 1 week earlier. Each run reads the Query twice, within the same 30 s. [docs/logs/monitors.md](../logs/monitors.md#comparing-the-change) has the rules.
  - A group with no row in the Baseline rises from 0, and one with no row now is ok, so "falls" misses a group that stops sending (alert on no data catches that).
  - An optional minimum keeps a group ok while both its number and its Baseline are under it.
  - Saving refuses a 1-day Baseline with a range over 1 day, as the two would overlap, and a Baseline reaching past the Project's Log Retention. A run that finds Retention has since been lowered is an error and changes nothing.
  - Switching a Monitor between the value and the change resolves its firing groups. Other edits leave them for the next run.
- **The form's preview** in change mode charts the last 24 hours now and over the Baseline on one chart, and lists the groups that would fire now, with their value, Baseline and change, by the run's own rule. Settings that saving would refuse are named in place of the list.
- **The Monitor's page** shows each group's last value, Baseline and change in their own columns, and its summary sentence reads the rule ("fires when the number rises by 50% or more from the 15 minutes before").
- **Messages** say what changed: "count_ was 120 over the last 15 minutes, up 100% from 60 the 15 minutes before", or "up from 0". Slack and email link to the Logs explorer over both ranges. PagerDuty adds the Baseline and the change to its custom details, with the same dedup keys.
- **MCP.** `create_monitor`, `update_monitor` and `get_monitor` take and return `compare`, `baseline` and `minimum`, and the operators `rises`, `falls` and `changes`. `get_monitor` gives each group's last Baseline, and `run_monitor` each group's change.

## Upgrading from v0.15.1

`deploy/install` runs Console's two migrations: Monitors gain `compare` (`value` for every existing Monitor), `baseline` and `minimum`, and group states gain `last_baseline`. Existing Monitors work as before. No config changes.

```bash
git fetch --tags && git checkout v0.16.0 && deploy/install
```
