# v0.24.2

A bug fix release. The Capture setup page gives a login command that works when the Ingest URL is `http://`. The review skills take a person's Atlassian API token for Bitbucket, and the setup wizard asks for it. It's still a 0.x prototype, not yet hardened for production.

## Fixed

- **The Capture setup page gave a login command that the CLI refuses:** the CLI sends tokens only over HTTPS, or to a loopback address. On an install with Console on `https://` and an Ingest URL on `http://`, such as `http://<host>:4000`, the page gave `solidtrace login --ingest-url http://<host>:4000 …`, and the CLI refused it. Now the page gives ingest's HTTPS address, `https://<ingest host>:4443`, where Caddy serves ingest with HTTPS on. Step 5's telemetry endpoint uses the same address. The SDK snippets and the DSNs keep the Ingest URL. See [docs/agent-sessions.md](../agent-sessions.md).
- **The review skills did not work with a person's Bitbucket API token:** they sent `BITBUCKET_TOKEN` as a Bearer token, which Bitbucket takes only for an access token of a repository, a project or a workspace. Bitbucket takes a person's Atlassian API token only with Basic auth and the account's email. Now, when `BITBUCKET_EMAIL` is set, `open-pr` and `update-pr` send Basic auth, so one token for each person works in each repository that they can open. Without `BITBUCKET_EMAIL`, they send the token as Bearer, as before. The API token needs the scopes `read:user:bitbucket`, `read:repository:bitbucket`, `read:pullrequest:bitbucket` and `write:pullrequest:bitbucket`.

## Changed

- **The setup wizard asks for the Bitbucket token:** when you install the review plugin and no `BITBUCKET_TOKEN` is set, a new stage opens Atlassian's API token page, names the scopes, and asks for the token and your Atlassian email. It checks them with Bitbucket, and writes `BITBUCKET_EMAIL` and `BITBUCKET_TOKEN` to `env` in `~/.claude/settings.json`, with mode 600. Press Enter to skip it. The question to install the review plugin is now `[Y/n]`: Enter is yes.

## Upgrading from v0.24.1

No migration, and no step to do by hand. `deploy/` has no change.

```bash
bin/upgrade v0.24.2
```

Each engineer gets the skills of this release when they run the setup wizard again. It updates the review plugin, and asks for the Bitbucket token:

```bash
curl -fsSL https://raw.githubusercontent.com/Shankar1598/solid_trace/main/cli/setup-claude-code.sh | sh
```
