# v0.4.0 (2026-10-19)

Charts can show requests per second now, and every time Chart says its bin size. It's still a 0.x prototype, not yet hardened for production.

## What's new

- **`rate()` and `peak_rate()` aggregates.**
  - `rate()` is the Logs per second, averaged over each bin. It counts only the part of a bin inside the range, so the edge bins read true.
  - `peak_rate()` is the Logs in each bin's busiest second. So a month's Chart, with 12-hour bins, still shows the true busiest second.
  - Both work in the Logs explorer, the Builder, Dashboards, Monitors and the MCP server. A Threshold monitor can fire on a peak rate.

  ```
  where path == "/v2/search" | summarize rate(), peak_rate() by bin_auto(time), shop
  ```

  A few rules (see "Requests per second" in `docs/logs/query-language.md`):
  - `peak_rate()` needs bins of whole seconds.
  - A time bin used with `rate()` must be of the Logs' own time.
  - A `where` on `time` goes first, so that it narrows the range `rate()` divides by.
- **A time Chart shows its bin size.** The size, such as `1m bins`, sits beside the legend, and the tooltip gives the bin's span, start to end.

## Upgrading from v0.3.0

There are no migrations and no config changes.

```bash
git fetch --tags && git checkout v0.4.0 && deploy/install
```
