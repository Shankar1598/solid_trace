# v0.24.1

A bug fix release. The Agent session page shows a shell command that a person runs with `!` once, with its output under it, as it shows a slash command. It's still a 0.x prototype, not yet hardened for production.

## Fixed

- **The Agent session page showed a shell command wrongly:** for a command that a person runs with `!`, such as `! terraform apply`, Claude Code writes the command in `<bash-input>` and its output in `<bash-stdout>` and `<bash-stderr>`, all as user lines. The page showed the command and its output as two person messages, with Claude Code's tags and the colour codes of the terminal (as `[0m [1m`). Now the command shows once, in mono, as `! terraform apply`, with its output under it after a ⎿ mark: the stdout and then the stderr, with no colour codes. The parse gives the output of a shell command the role "not from a person": the output is not a person message, not a turn, and not the title of an Agent session. A shell command as the first person message gives the title `!` and the command. Logs that SolidTrace parsed before this release keep the role "person" for the output; the page still shows the output under the command. See [docs/agent-sessions.md](../agent-sessions.md).
