# v0.18.0 (2026-10-30)

Moves the budget of a Query that matches text to Settings → Instance, so an Instance admin changes it with no restart. It's still a 0.x prototype, not yet hardened for production.

## Changed

- **The text-match budget is an instance setting.** The most a Query that matches text (`search`, or `contains`, `startswith`, `=~` or `matches regex` on `message`) may read before the Logs explorer and MCP refuse it is set on Settings → Instance, or with `update_instance_settings` over MCP, and applies from the next Query. It's still 4 GiB by default, and 0 refuses none. A Query over a quarter of it is still a heavy read. v0.17.0 read it from `event_store.yml`, which took an EventStore restart to change.
- **Settings → Instance shows the heavy-read slots** (`logs_heavy_read_slots`, "Heavy Log reads at once") among EventStore's settings that take a restart. They stay in `event_store.yml`, as EventStore sizes them at start from the CPU count.

## Upgrading from v0.17.0

`deploy/install` runs Console's migration: `instance_settings` gains `logs_text_match_budget_mb`, 4096 for every install. If your `config/event_store.yml` sets `logs_text_match_budget_mb`, EventStore now ignores it and warns at start: set the same value on Settings → Instance after the install, then remove the key.

```bash
git fetch --tags && git checkout v0.18.0 && deploy/install
```
