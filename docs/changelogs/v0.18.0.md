# v0.18.0 (2026-11-04)

Adds KQL's `extract`, `substring`, `round` and `parse_json` to the Query language, so values in messages can be taken out with `query_logs` and the Logs explorer, under the text-match budget, rather than with SQL. Moves that budget to Settings → Instance, so an Instance admin changes it with no restart. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Functions to take values out of messages.** [docs/logs/query-language.md](../logs/query-language.md#scalar-functions) has each, and the Query box suggests them.
  - `extract(regex, group, s)` gives what a regex's capture group matched, as in `toint(extract("keys=([0-9]+)", 1, message))`.
  - `substring(s, start [, length])` cuts characters from a zero-based start, and a negative start counts back from the end.
  - `round(x [, precision])` rounds to digits after the point, or before it when negative. A half rounds away from zero.
  - `parse_json(s)` reads a JSON message. `.name`, `["name"]` and `[0]` reach a member or an element at any depth, as in `parse_json(message).result.cache_keys_expired`, and `[-1]` is an array's last element. `array_length(x)` counts an array's elements. `[…]` reaches into an Attribute that holds an array or object too. A dotted name on its own, such as `tags.store_id`, is still one Attribute (ADR 0002 has the amendment).
- **MCP.** `query_logs`' description names the new functions, and `run_sql`'s says `query_logs` takes values out of messages too.

## Changed

- **The text-match budget is an instance setting.** The most a Query that matches text may read before the Logs explorer and MCP refuse it is set on Settings → Instance, or with `update_instance_settings` over MCP, and applies from the next Query. It's still 4 GiB by default, and 0 refuses none. A Query over a quarter of it is still a heavy read. v0.17.0 read it from `event_store.yml`, which took an EventStore restart to change.
- **A function of `message` matches text.** A Query matches text with `search`, with `contains`, `startswith`, `=~` or `matches regex` on `message`, and now with a function of `message` anywhere in it, such as `where strlen(message) > 1000` or `summarize count() by extract(…, message)`. A column that holds `message` as it is, renamed or not, counts as `message`. So over the budget, the Logs explorer and MCP refuse these as they refuse a search, with a narrower Query that fits. `project message` on its own doesn't match text, and Dashboard Charts and Monitors still always run.
- **Settings → Instance shows the heavy-read slots** (`logs_heavy_read_slots`, "Heavy Log reads at once") among EventStore's settings that take a restart. They stay in `event_store.yml`, as EventStore sizes them at start from the CPU count.
- **rack 3.2.8** in Console, fixing GHSA-5v64-555j-wjxm: rack's multipart parser could keep a whole request in memory.

## Upgrading from v0.17.0

`deploy/install` runs Console's migration: `instance_settings` gains `logs_text_match_budget_mb`, 4096 for every install. If your `config/event_store.yml` sets `logs_text_match_budget_mb`, EventStore now ignores it and warns at start: set the same value on Settings → Instance after the install, then remove the key.

```bash
git fetch --tags && git checkout v0.18.0 && deploy/install
```
