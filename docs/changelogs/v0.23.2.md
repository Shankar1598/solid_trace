# v0.23.2

The Agent sessions list and the Agent session page show the title of each Agent session, the one that Claude Code shows. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Agent session titles:** the Agent sessions list has a Title column first, and the Agent session page has the title as its heading. The title is the last name that a person gave the Agent session with `/rename`, else the last title that Claude Code made for it, else the start of its first person message. A subagent's title lines do not change it. A long title is cut with "…" in the list, and the hover text has all of it. On a phone, the title is the main text of the row. An Agent session with no title shows the start of its id, in grey. `list_agent_sessions` and `get_agent_session` over MCP give the title too. See [docs/agent-sessions.md](../agent-sessions.md).

## Upgrading from v0.23.1

EventStore adds the `title` column to its ClickHouse table `agent_sessions` (step 11202, `ALTER TABLE … ADD COLUMN IF NOT EXISTS`) when it first starts. No other migration, and no step to do by hand. `deploy/` has no change.

An Agent session that EventStore parsed before the update has no title, and shows the start of its id. EventStore does not parse a stored transcript again: the parse reads each upload one time, and a second parse would add its tokens to the totals again. An Agent session that continues after the update gets a title when its new lines have one: Claude Code writes its title again as the Agent session goes on, and a `/rename` gives one too. Its first person message is in its old lines, so it never gets that as its title. This release has no step that gives the old Agent sessions their titles.
