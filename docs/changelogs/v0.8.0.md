# v0.8.0 (2026-10-21)

The Logs explorer reads faster and costs the server less, EventStore runs on Go 1.27, and Console can time the MCP server's calls and Log reads. It's still a 0.x prototype, not yet hardened for production.

## What's new

- **Faster Log reads.**
  - The newest page reads each hour in two steps: times and ids first, then those Logs whole. Over 300k Logs, a page from the hot table went from 323 to 52 ms, and from a Log file from 366 to 106 ms.
  - Text operators and `search` no longer use `ILIKE`/`LIKE`: `contains` is 2 to 3.5× faster, `contains_cs` 3 to 4.4×, `search` about 2×. Bins cached before the upgrade are worked out again once.
  - The explorer's histogram takes its bins from the bin cache. A Log file hour's histogram drops from 26 to 3 ms when reopened.
- **The hourly export no longer stalls Log processing.** It copies Logs outside the write lock, so Logs arriving during the export wait under half a second, not several seconds to minutes.
- **EventStore on Go 1.27.** Log ingest is 18–29% faster, a page of 200 Logs 60% faster, and Event parsing 22% faster. One change in answers: an invalid UTF-8 byte is written as U+FFFD itself, not as its `�` escape.
- **Call timings.** Console writes one line per MCP tool call and per Log read (Query, histogram, SQL, Match monitor run), with its duration, outcome, user, origin, the Query or SQL text and the release's version. EventStore logs each SQL statement a read ran (`kind=log_read_sql`), joined by `request_id`. On a VM install, Vector ships both to the Meta Organization's SolidTrace Project.
  - By default only the MCP server's calls and reads are timed. To time every read, the explorer's and Dashboards' too:

    ```bash
    sudo docker compose -f deploy/docker-compose.yml exec console bin/rails instance_settings:set LOG_ALL_READS=true
    ```
- **CPU profiles, off unless asked for.** With `cpu_profile_dir` set in `deploy/event_store.yml`, EventStore writes a 30-second CPU profile at half a minute past each hour, during the export, and at half past, keeping the newest 48.

## Upgrading from v0.7.0

One migration adds `instance_settings.log_all_reads`. Console runs it when it starts, so there's nothing to do by hand. There are no required config changes; `cpu_profile_dir` is new and optional.

```bash
git fetch --tags && git checkout v0.8.0 && deploy/install
```

## Install

On a Debian or Ubuntu machine, x86 or Arm:

```bash
git clone --branch v0.8.0 https://github.com/Shankar1598/solid_trace.git
cd solid_trace
deploy/setup-gcp
```

Images, for `linux/amd64` and `linux/arm64`:

- `ghcr.io/shankar1598/solid-trace-console:v0.8.0`
- `ghcr.io/shankar1598/solid-trace-event-store:v0.8.0`
