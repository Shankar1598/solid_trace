# v0.2.0 (2026-10-19)

SolidTrace keeps its own logs now, and its images run on Arm VMs as well as x86. It's still a 0.x prototype, not yet hardened for production.

## What's new

- **SolidTrace's own Logs.** On a VM install, Vector reads every SolidTrace container's output from Docker and sends it to the "SolidTrace" Organization and Project, which `db_prepare` makes once. The first user to sign up becomes its admin (on an existing install, the oldest user). If you delete it, it stays deleted. See [ADR 0011](../adr/0011-meta-organization-and-vector-reads-docker-logs.md).
- **Key-only Log ingest.** `POST /api/logs` finds the Project from the project key alone. The Logs page's curl, Vector and Fluent Bit snippets use it. `/api/<project id>/logs` still works.
- **amd64 and arm64 images.** Both images are built for both architectures, so GCP's T2A and other Arm VMs pull native images.
- **Install from images only.** `deploy/install` always pulls a release's images: the one the checkout is at, or the newest release before it. It no longer builds on the VM. `deploy/install --build` builds from the checkout.
- **The install's last screen shows the Log shipping URLs.** The VPC one is the internal IP on port 4000; the outside one is the public ingest URL.
- **Auto-refresh.** Dashboards and the Logs explorer refresh every 15 seconds by default.
- EventStore logs each file it uploads to the bucket. The message queue's rows are deleted after 30 days. Console's production log lines start with their Level, and EventStore's logs have no colour codes off a terminal.

## Install

On a Debian or Ubuntu machine, x86 or Arm:

```bash
git clone --branch v0.2.0 https://github.com/Shankar1598/solid_trace.git
cd solid_trace
deploy/setup-gcp
```

To upgrade from v0.1.0: `git fetch --tags && git checkout v0.2.0 && deploy/install`. The install writes the Meta Organization's project key to `deploy/.env` and seeds the Organization.

Images, for `linux/amd64` and `linux/arm64`:

- `ghcr.io/shankar1598/solid-trace-console:v0.2.0`
- `ghcr.io/shankar1598/solid-trace-event-store:v0.2.0`

## Release record

Ships images for amd64 and arm64 on ghcr.io, built on native runners by `.github/workflows/release.yml` (also runnable by hand with a tag). `deploy/install` now always pulls a release's images (the checkout's tag, or the newest before it) and stops if a pull fails; `--build` builds from the checkout. The user is installing on GCP T2A (arm64) VMs.
