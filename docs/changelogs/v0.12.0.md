# v0.12.0 (2026-10-23)

Adds Dashboard filters. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Dashboard filters.** A filter bar under a Dashboard's header: selects, from a fixed list or a field's most common values, with one value or several, and search boxes. A Chart uses a filter by naming it in its Query, such as `where service == $service`. With several values, `==` and `contains` match any of them and `!=` matches none. A filter on All drops its comparison. Values go in the URL as `v_<name>`, and only the Charts that name a changed filter run again. Set up filters from the Filters dialog. The Chart editor's Builder shows them as chips.
- **MCP.** `create_dashboard` and `update_dashboard` take `filters`, `get_dashboard` lists them, and `get_chart_data` runs a Chart with filter values. `add_chart` and `update_chart` refuse a Query that names a filter the Dashboard doesn't have. A Monitor's Query can't name a filter.

## Changed

- **`$` no longer starts a field name.** A bare `$type` in a Query now names a filter, which is All when it isn't set. Write a field named `$type` as `['$type']`.

## Upgrading from v0.11.1

One migration, `AddFiltersToDashboards`, which runs on start. No config changes.

```bash
git fetch --tags && git checkout v0.12.0 && deploy/install
```

From a DuckDB release, upgrade straight to v0.12.0: its `deploy/install` runs v0.10.0's `prepare-clickhouse`, as v0.11.x's did.
