# v0.23.3

`list_agent_sessions` gives fewer and shorter rows, so that an MCP client can read all of its answer. An Agent session's activity is only the times of its lines that have a timestamp, so an Agent session that uploads again does not show as active at the upload time. The Agent sessions page shows its Run filters only with the Factory on, and the agent's replies as Markdown. It's still a 0.x prototype, not yet hardened for production.

## Fixed

- **`list_agent_sessions` answers were too large:** 255 Agent sessions gave about 160,000 characters, more than an MCP client reads in one answer. The tool now gives at most 50 rows, or its new `limit` argument, at most 200. The totals are still of all the Agent sessions that the filters select, and `more` is true when the limit left some out: the description tells the agent to narrow the range, or to filter by person or repository. Each row leaves out the fields with no value (an empty folder, parent Agent session, model or flags, no Run, no cost), as `get_issue` leaves out the empty parts of an Event. The title stays, also when it is `""`. The Agent sessions page keeps its limit of 500. See [docs/mcp.md](../mcp.md).
- **An Agent session that uploaded again showed as active at the upload time:** Claude Code writes many lines with no timestamp (its title, the last prompt, the mode, the permission mode, the cost state and more). The parse gave such a line the time of the line before it, and the first lines of each upload part the time when the server stored the part. Those times went into the Agent session's first and last activity. So, after an Agent Project was deleted and its Agent sessions uploaded again, a 2-hour list showed nearly all of them, with the upload time as their last activity. Now a line with no timestamp of its own is not activity. Its Log still has a time in the Logs explorer. A transcript with no line that has a timestamp has no activity: it is in no time range, and its page shows the time when SolidTrace stored it. Agent sessions that SolidTrace parsed before this release keep their times: EventStore does not parse a stored transcript again. See [docs/agent-sessions.md](../agent-sessions.md).

## Changed

- **Agent sessions page:** the **Project (Runs)** and Run filters show only when the Factory is on. The Project list holds only the Projects whose Runs have Agent sessions in the range, as EventStore's list answers them, and the Project of the current filter.
- **Agent sessions page:** an open filter list is as wide as its longest choice.
- **Agent session page:** the agent's replies and its thinking show as Markdown. A person's messages stay plain text.

## An Agent session with no title after the update to v0.23.2

A live Agent session of a real install had no title after the update to v0.23.2, although its transcript had 59 lines with a title from Claude Code. Its lines with a title uploaded and were parsed before the update, by v0.23.1, which had no titles. Its only part after the update had no title line. This is the documented case "an Agent session that SolidTrace parsed before v0.23.2 has no title". The Agent session gets its title at its next turn, when Claude Code writes its title again. Tests now prove that v0.23.2's parse gives the last title to an Agent session that uploads in many small parts (parts that end on a title line, parts of only lines with no timestamp, two stored days, a subagent between the parts, a new version of the transcript).

## Upgrading from v0.23.2

No migration, and no step to do by hand. `deploy/` has no change.

```bash
bin/upgrade v0.23.3
```
