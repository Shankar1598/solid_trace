# v0.23.1 (2026-11-23)

The Agent session pages are easier to read, `solidtrace capture status` checks each setup step, and the Capture setup page gives plugin commands that work with Claude Code. Security updates for Go, a Rust crate and two gems. It's still a 0.x prototype, not yet hardened for production.

## Changed

- **Agent sessions list:** a click anywhere on a row opens the Agent session.
- **Agent session page:**
  - Each tool call is one line that opens to its input and output. A run of 3 or more tool calls is one group.
  - A tool call that started a subagent shows as "Subagent: <description>".
  - Person messages are the strongest. Thinking is quiet text. A slash command reads as the command, and the text that Claude Code adds to it folds.
  - "Show tool calls" and "Show agent thinking" toggles, which the browser keeps.
- **`solidtrace capture status`** checks each setup step (the sign-in, the Claude Code plugin, the captured repositories list and the uploads) and says what to do for each one that fails. It counts the Agent sessions; `--all` lists each one. "not in the list" is now "not captured".

## Fixed

- **The plugin install commands** on Settings → Agent sessions → Capture setup, in [docs/agent-sessions.md](../agent-sessions.md) and in the plugin's README. With Claude Code 2.1.323, `claude plugin marketplace add <release URL>/marketplace.json` fails (Claude Code clones a github.com URL as a git repository), and a downloaded `marketplace.json` added as a plain file installs but does not load ("cache-miss"). The commands now download the file into `~/.local/share/solidtrace/.claude-plugin/` and add that path, and `claude plugin list` checks that the plugin is enabled. With managed settings, the plugin runs from the second start of Claude Code.

  An engineer who installed the plugin from v0.23.0's page: run `claude plugin list`. If it says "failed to load", run `claude plugin marketplace remove solidtrace`, then the new commands.

## Security

- The CLI, the wrapper and the agent CLI are built with Go 1.27.4, for GO-2026-6859 in `net/http`, which the CLI reached. EventStore was on Go 1.27.4 already.
- EventStore's VRL: the `url` crate 2.5.9, for RUSTSEC-2026-0592.
- Console: `net-ssh` 7.3.10 (one high and one medium advisory; only `kamal`, the deploy tool, needs it), and Brakeman 8.1.1.
