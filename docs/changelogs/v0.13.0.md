# v0.13.0 (2026-10-24)

Adds the Overview, Instance settings, and Project descriptions for agents. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Overview.** A page per Organization, first in the sidebar, of what came in, what was kept and what it costs, over Today, 7 or 30 days (whole UTC days).
  - **The band.** Received → Kept → Stored, each step as wide as its bytes, with the Logs dropped as unreadable or by the Log transform, and the compression ratio.
  - **Rates.** Logs, bytes and requests per second, each as an average and the busiest second.
  - **Daily Charts** of Logs by Project, bytes received and stored, and Logs per second.
  - **Projects:** sizes, ratio, share, rates, Retention, oldest day kept, and when the last Log arrived.
  - **Biggest sources:** the Services and files that send the most Logs and bytes. Each opens the Logs explorer.
  - **Health:** how long Log processing keeps a Log batch waiting, Log read times over the last 24 hours, failing and Firing Monitors, and new Issues and Events.
  - **Compared with other tools:** what the volume would cost a month at Datadog's, Better Stack's and Axiom's list prices (checked 2026-10-24), plus GCP's internet egress.
  - **Storage**, for Instance admins: the whole install's local disk against the disk limit, the bucket, the disk at steady state, and the old Parquet files still kept.
  - The page never reads the Logs themselves. EventStore counts what arrives per second and what is kept per Service and file, in two small ClickHouse tables that Retention and Project deletion clean up.
- **Settings → Instance**, for Instance admins:
  - change SQL queries, the default Retention, Log all reads and Log MCP reads;
  - see Sign-up, read-only;
  - see Console's environment and EventStore's loaded config under "Restart to change", with secrets shown only as set or not set.
- **Settings → API tokens & MCP**, a page of its own for your tokens and the MCP URL.
- **Project descriptions.** A Project can say what it holds, so agents can tell which Project to query.
- **MCP:**
  - `get_overview` answers the Overview.
  - `get_instance_settings` and `update_instance_settings` read and change the install's settings.
  - `update_project` changes a Project's description or Retention.
  - `create_project` takes a description, and `list_projects` answers it.

## Changed

- **Logs reopens the Project you last opened.** The sidebar's Logs entry opens the Project whose Logs you last opened in that Organization, not the newest.
- **Shorter MCP server instructions.** How to write a Log transform now comes only from `get_log_transform`.
- **MCP read timing.** MCP reads are timed only while Log MCP reads or Log all reads is on.

## Upgrading from v0.12.0

Two Console migrations, `AddDescriptionToProjects` and `AddLogMcpReadsToInstanceSettings`, and two new ClickHouse tables, all made on start. No config changes. The Overview's arrival and source counts start from the upgrade; stored sizes go back as far as Retention keeps Logs.

```bash
git fetch --tags && git checkout v0.13.0 && deploy/install
```

From a DuckDB release, upgrade straight to v0.13.0: its `deploy/install` runs v0.10.0's `prepare-clickhouse`, as v0.12.0's did.
