# v0.3.0 (2026-10-19)

Log files in the bucket now sit in their own `logs/` folder, beside the Event archive's `events/`. It's still a 0.x prototype, not yet hardened for production.

## What's changed

- **Log files go under `logs/` in the bucket.** A Log file's key is now `<prefix>logs/project=<id>/day=<date>/hour=<hour>/<file>.parquet`, beside `<prefix>events/…`. So lifecycle rules, access and outside tools (BigQuery, DuckDB, Spark) can each target one kind of data by its prefix. Local paths are unchanged.

## Upgrading from v0.2.0

**This breaks installs that use a bucket (`object_store`).** Log files already uploaded stay at their old keys and aren't moved, but EventStore now looks for them under `logs/`. Once their local copies are evicted (after `local_cache_hours`, 24 by default), reads of those hours fail. Before upgrading such an install, empty the bucket's Log files and delete `logs.duckdb`, which drops the install's Logs. Installs without a bucket aren't affected.

```bash
git fetch --tags && git checkout v0.3.0 && deploy/install
```

## Install

On a Debian or Ubuntu machine, x86 or Arm:

```bash
git clone --branch v0.3.0 https://github.com/Shankar1598/solid_trace.git
cd solid_trace
deploy/setup-gcp
```

Images, for `linux/amd64` and `linux/arm64`:

- `ghcr.io/shankar1598/solid-trace-console:v0.3.0`
- `ghcr.io/shankar1598/solid-trace-event-store:v0.3.0`
