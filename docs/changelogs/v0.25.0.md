# v0.25.0

A feature release. `solidtrace resume` continues an Agent session on any machine. Dashboards get SQL Charts with filters. Monitors hold while their Logs are not complete after a restart, and one Integration hears when Monitors do not run. Capture and the review skills are one Claude Code plugin, from a marketplace in the repository. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Evidence files open in a popup.** On the Agent session page and the Review record page, a click on an Evidence file opens it in a popup on the same page: the image fit to the window, or the video with its speed control, the whole caption, "n of N" with the previous and the next file (the buttons, or ← and →), and **Open page**. Esc closes it. A click with Ctrl, Cmd, Shift or the middle button still opens the file's page.
- **The PR body on the Review record page.** `solidtrace review record --pr-body FILE` keeps the PR body in the record's new `pr_body` (the version stays 2), and refuses a body of more than 65,536 characters, GitHub's limit. `open-pr` and `update-pr` give it the body that they wrote. The page shows it as Markdown before the Story, with the rules of a Text block, and `get_review_record` gives it. A record from plugin 0.24 or earlier has no PR body, and the page says so.
- **`/solidtrace:setup-solidtrace-skills`.** It installs the pstack plugin when it is not there, runs pstack's model setup when `pstack-models.md` is not current, and installs `/wait-what` from `mattpocock/skills` and `deslop` from `cursor/plugins` (`npx skills add`) when they are not there. It asks whether to set them up for this repository (the default: `.claude/settings.json`, `.claude/rules/`, `.claude/skills/` and `skills-lock.json` in the repository) or for this user (`~/.claude`). `open-pr` and `update-pr` now write the PR body as the re-pitch that `/wait-what` asks for, when it is installed: in this repository's version, a little context, ASD-STE100 Simplified Technical English, and the words of `GLOSSARY.md`. The Review section of the body puts the risks first, in three groups: **Check these before you merge** (deferred, disputed, accepted and open findings, and the checks that did not run), **Fixed by the reviews**, and **Changed outside the reviews**. Each finding starts with its type: Bug, Spec, Test, Code quality, HA and infrastructure, or Security.
- **The PR body says what to skim and what no test covers.** In Where to look, `open-pr` and `update-pr` name the files that a reviewer can skim (generated files, lockfiles, test data, renames and moved code). In Evidence, they name each changed behavior that no test covers.
- **`open-pr` cleans up the code before the final review.** When the `deslop` skill is installed, `open-pr` follows it on the branch's diff, runs the tests of the changed files, and commits the cleanup before the deep review starts. `/solidtrace:setup-solidtrace-skills` installs `deslop` from `cursor/plugins`.
- **`/solidtrace:beta-pr-review-canvas` (beta).** It makes an HTML page that walks a reviewer through a Bitbucket or GitHub PR, or the PR file of `open-pr local`: the summary and the risks of the PR body first, the core files open with notes, and the files to skim collapsed. Code that moved shows in blue or purple. It serves the page on `127.0.0.1:8432`. It is a copy of `pr-review-canvas` from Cursor's `cursor-team-kit` (MIT).
- **Resume an Agent session on another machine.** `solidtrace resume SESSION_ID [--print] [-- CLAUDE_ARGS...]` continues an Agent session. Run it in a checkout of the repository of the Agent session. On the machine where the Agent session started, it starts `claude --resume SESSION_ID` in its start folder, with the same id. On another machine, it downloads the Agent session into a temporary folder, not into a Claude Code project folder, and starts a new Agent session with a new id from its history (`--fork-session`). The first Agent session does not change, and the page of the new Agent session links to it as its **Parent Agent session**. Saved tool outputs of the first machine are not readable after a resume on another machine. The command tells you how to get the branch of the Agent session, and refuses with what to do in a checkout of another repository, with an old sign-in, or when the transcript is partial or cut. The Agent session page shows the command under **Resume on another machine**, with **Copy**. See [Resume an Agent session on another machine](../agent-sessions.md#resume-an-agent-session-on-another-machine).
  - The new Scope `sessions:download` downloads each Agent session of the Organization's Agent Project. `solidtrace login` asks for it, and you can put it on your own API token. A child token never has it. It gives no new access: each member reads these Agent sessions in Console.
  - Capture finds the start folder of the new Agent session on this machine. It never finds the downloaded transcript, so it uploads no copy of another person's or a Run's Agent session.
- **SQL Charts on Dashboards, with filters.** While SQL queries are on, the chart editor has a SQL tab, and a Chart can save a SQL query in place of a Query. The SQL names a Dashboard filter as a ClickHouse query parameter: `{name:Array(String)}` for a select, `{name:String}` for a search box, or `{name:Nullable(String)}`, and ClickHouse fills in the values. A SQL Chart runs again when its filters change. It draws a time series when its first column is a time, bars when it has no time column, and a single number for one row of one number. The MCP tools `add_chart` and `update_chart` take `sql`, and `get_chart_data` runs SQL Charts. A Monitor's SQL can't name a filter. See [Dashboard filters in SQL](../logs/query-language.md#dashboard-filters-in-sql) and [ADR 0026](../adr/0026-dashboard-filters-in-sql-are-clickhouse-query-parameters.md).
- **A Monitor status Integration.** In Settings → Organization → Monitor status, an Organization chooses one Slack, PagerDuty or email Integration, or None. When Monitors that are on do not run for 2 minutes, it gets one "not running" message with each Monitor, since when and why, and one "running again" message when they run again. A restart makes one message of each kind. The Monitors list shows "Not running since" beside each Monitor that does not run. See [When Monitors do not run](../logs/monitors.md#when-monitors-do-not-run).

## Changed

- **One Claude Code plugin.** The `solidtrace` plugin now has capture and the review skills, and the `solidtrace-skills` plugin goes. The skills have new names: `/solidtrace:code-review`, `/solidtrace:deep-review`, `/solidtrace:open-pr`, `/solidtrace:update-pr` and `/solidtrace:try-pr`. The setup script installs the `solidtrace` plugin and removes `solidtrace-skills`. `SOLIDTRACE_REVIEW_PLUGIN=no` goes, because the skills are in the same plugin as capture. Records of earlier sessions stay as they are: the digest finds a review skill by the last part of its name, so `solidtrace-skills:code-review` and `solidtrace:code-review` are the same to it.
- **The marketplace is in the repository.** Claude Code adds the SolidTrace marketplace from GitHub at the release's tag: `claude plugin marketplace add Shankar1598/solid_trace#<tag> --sparse .claude-plugin cli/plugin`. It clones only those two folders. The release no longer has `marketplace.json` or a plugin zip. Capture setup's commands and managed-settings snippet give the `github` source at the instance's release. The release commit sets the version in `cli/plugin/.claude-plugin/plugin.json`, and the release job fails when it is not the tag's version.
- **Ingest takes Logs while ClickHouse starts.** EventStore takes Logs and Events at once, and waits for ClickHouse itself. Until ClickHouse answers, it answers no reads, and `/health` says that ClickHouse is starting. In `deploy/docker-compose.yml`, EventStore now waits for ClickHouse to start, not to be healthy. The health of the public ingest port gives no error text.
- **A Threshold run is held while the Project's Logs are not complete:** while Log processing is more than a minute behind, and for 1 to 10 minutes after EventStore was down, while the senders send the Logs that they kept. A held run compares nothing and sends nothing, so a restart does not fire **alert on no data** or a "too few" threshold. The run history shows each held run with its reason. SQL Monitors hold on the Logs only. See [ADR 0027](../adr/0027-threshold-monitors-hold-while-their-logs-are-not-complete.md) and [Monitors](../logs/monitors.md).
- **The Claude Code setup asks no questions.** The setup script installs or upgrades with no prompts, signs in only from `SOLIDTRACE_CONSOLE_URL` and `SOLIDTRACE_INGEST_URL`, and lists what is still to do. Before, it asked for the Console and Ingest URLs on each upgrade, also on a machine that was signed in.
- **The MCP server's Query language reference** has the section Dashboard filters in SQL.

## Fixed

- **No raw comment at the end of a Bitbucket PR.** `open-pr` and `update-pr` end the PR body with the visible line `SolidTrace Review record · round N`, in place of the `<!-- solidtrace-record round N -->` comment, which Bitbucket showed as text. `update-pr` still reads the old comment on PRs that are already open.
- **No empty runs in a Review record.** A findings block that cannot be read (a block that Claude Code's output limit cut, or a block that came back in a subagent's report) no longer makes a review run with no skill, stage, reviewers or verifier. `solidtrace review record` warns that the record has none of its findings, and a review start that only such a block follows is a run of its own, with the start's skill.
- **The Review record page.** A run that a record already has with no skill, stage, reviewers or verifier shows one muted line: "No data: the findings block of this run could not be read." The Details of a finding wrap long paths, so they stay in their cell.

## Upgrading from v0.24.3

Upgrade the install first. Console runs its three new migrations (`dashboard_charts.language`, the holds of Monitors, and the Monitor status Integration of Organizations) when it starts. EventStore has no new migration.

```bash
bin/upgrade v0.25.0
```

Upgrade Console and EventStore first. Then each engineer runs the setup script again, and then `solidtrace login` again, so that the sign-in has `sessions:download`. A new CLI cannot sign in to an older Console, because the older Console does not know the Scope `sessions:download`. Until an engineer signs in again, a resume on another machine tells them to run `solidtrace login`, and capture works as before. A new CLI with an older EventStore captures as before too. On another machine, `solidtrace resume` then tells the engineer to ask the operator to upgrade, because the older EventStore refuses the download.

The setup script removes the old `solidtrace` marketplace (the downloaded `marketplace.json`) with its plugins, also `solidtrace-skills@solidtrace`, so each skill does not show two times. It then adds the marketplace from GitHub and installs `solidtrace@solidtrace`. You can delete `~/.local/share/solidtrace/.claude-plugin/`. Then restart Claude Code, and use the new names, such as `/solidtrace:open-pr`.

If your managed settings have the `solidtrace` marketplace with a `url` source, change it to the new snippet on the Capture setup page.
