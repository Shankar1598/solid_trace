# v0.23.4

The Agent sessions page sorts by the start, the last activity, the tokens or the estimated cost, and `list_agent_sessions` sorts in the same way. It's still a 0.x prototype, not yet hardened for production.

## Added

- **Agent sessions page: sort by a column.** Click the heading of **Start**, **Last activity**, **Tokens** or **Estimated cost** to sort the list by it. The first click shows the latest times, the most tokens or the highest cost first; a second click turns the order around. An arrow next to the heading shows the sorted column and its direction; the other sortable headings show a quiet up-down arrow on hover and on focus. **Tokens** sorts also on a phone. EventStore sorts all the Agent sessions that the filters select before it takes the 500 rows of the page, so the most expensive Agent sessions of a range are always on the page, also when the range has more than 500. Agent sessions that tie go by id, so the rows are always the same. An Agent session with no cost comes after those with a cost, in both directions. The order is in the page's URL (`sort` and `direction`), and a change of the range or a filter keeps it. See [docs/agent-sessions.md](../agent-sessions.md).
- **`list_agent_sessions` takes `sort` and `direction`:** `sort` is `last` (the default), `start`, `tokens` or `cost`, and `direction` is `desc` (the default) or `asc`, as on the page. So an agent can ask for the most expensive Agent sessions with `sort: cost`. The answer gives the order, and its link opens the page in that order. See [docs/mcp.md](../mcp.md).
- **EventStore's list of Agent sessions** (`POST /api/:project_id/agent-sessions`) takes `sort` and `direction` with the same values. Any other value gets 400. The limit applies after the sort.

## Changed

- **Agent sessions page:** the person or the Run of a row is plain text, not a link of its own: a click anywhere on the row opens the Agent session, and the title stays the row's link.
- **Agent sessions page:** when the limit leaves Agent sessions out, the note under the list says the order of the rows, as "The first 500 of 812 Agent sessions, most tokens first".

bin/upgrade v0.23.4
