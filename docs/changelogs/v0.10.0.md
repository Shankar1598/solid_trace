# v0.10.0 (2026-10-23)

The last DuckDB release. It ships `prepare-clickhouse`, which readies a DuckDB install's Logs for the ClickHouse release, v0.11.0. It also moves email settings into Console and gives Console one request line per request. It's still a 0.x prototype, not yet hardened for production.

## What's new

- **`event_store prepare-clickhouse`.** It exports every Log still in DuckDB to Log files. Then it writes the manifest, promoted sets, key counts and Processing cursors beside `logs.duckdb`, with a marker. v0.11.0's `deploy/install` runs it from this release's image, so you don't run it by hand.
- **Email settings in Console.** Instance admins set the SMTP server and sender on Settings → Email, which sends a test email, or over MCP with `get_email_settings`, `update_email_settings` and `send_test_email`. The password is encrypted with a key derived from `SECRET_KEY_BASE`. The first user to sign up is an instance admin; on upgrade, the oldest user is. `bin/rails instance_admins:grant` makes others.
- **One request line per Console request.** Production Console writes one JSON line per request (`kind:"request"`), with its user, `request_id`, filtered params and `duration_ms`, in place of Rails' Started/Processing/Completed lines. Thruster's request line is off. Call-timing lines gain `user_name`, and EventStore's `Log read SQL` lines gain `user_email` and `user_name`.
- **MCP** tells agents about the Log file order, so their Queries, Charts and Monitors read less.

## Behaviour changes

- **Console no longer reads `SMTP_*` or `MAIL_FROM`** from `deploy/.env`. An install that sent email sends none until an instance admin fills in Settings → Email. `deploy/setup-gcp` no longer asks for SMTP settings, and says so if `deploy/.env` still has them.
- **Exception and warning lines** no longer carry `[request-id]`. The request line has it.
- **Requests that 404 in the router** get no request line.

## Upgrading from v0.9.0

Three migrations add the email settings and instance admins. Console runs them when it starts, so there's nothing to do by hand. If you sent email, copy the `SMTP_*` and `MAIL_FROM` values into Settings → Email, then delete them from `deploy/.env`.

```bash
git fetch --tags && git checkout v0.10.0 && deploy/install
```

You don't have to install this release before v0.11.0: v0.11.0's `deploy/install` pulls its image to run `prepare-clickhouse`.
