# A Meta Organization holds SolidTrace's own Logs, shipped by Vector from Docker

A VM install sends its own logs into itself. `db_prepare` seeds the **Meta Organization**, an Organization called "SolidTrace" with one Project, before the other services start, so Logs are kept from the first second. Its project key is generated by `deploy/install` into `deploy/.env`. Vector, one more Compose service, reads every SolidTrace container's output through the Docker socket and sends it to Log ingest's key-only route, `POST /api/logs`, on localhost.

A future reader may wonder why an install creates an Organization nobody asked for, and why Vector holds the Docker socket instead of reading log files. Both are this decision.

## Considered options

- **Each service writes log files to `deploy/logs/`, and Vector tails them:** Vector remembers its place across restarts, but every service needs file output, the uid 1000 images need the folder's ownership, and each file needs rotation. Once the lines are Logs in SolidTrace, the files are only a second copy.
- **Vector reads Docker's `json-file` logs under `/var/lib/docker/containers`:** remembers its place, but needs a different log driver, and the files are outside `deploy/`. Not worth it to close a gap of a few seconds.
- **The Project is created in the first Organization a user makes:** no Organization nobody asked for, but Logs before the first sign-up are lost, and existing installs need a second path.
- **The user creates the Project and pastes its key into `deploy/setup-gcp`:** no seeding, but nothing is shipped until they do.
- **Vector uses `/api/<project id>/logs`:** the id is known only after Console creates the Project, while Vector's config is fixed at start. A key-only route avoids that, and serves every shipper.

## Consequences

- Vector's access to the Docker socket is root-equivalent on the VM.
- Lines written while Vector is down, on an upgrade or reboot, are not shipped. They stay in `docker compose logs` until the container is replaced.
- Deleting the Meta Organization or its Project turns the feature off for good: a flag stops it being seeded again, and Vector's requests get a 401.
- The Meta Organization is an ordinary Organization. Its first admin is the first user to sign up, or the oldest user on an existing install.
