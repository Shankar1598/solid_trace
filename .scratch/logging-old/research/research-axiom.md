# Prior research: axiom

> Extracted from workflow run `wf_25055e4a-726` (solidtrace-logs-discovery, 2026-09-13, Fable subagents). Reference only: claims were not re-verified and design implications were never decided.


## Summary

Axiom is a schemaless, dataset-oriented log/event platform whose UX benchmark rests on five pillars: (1) a dead-simple HTTP ingest API (POST /v1/ingest/DATASET_NAME with Bearer API token; JSON array, NDJSON or CSV bodies; optional timestamp-field/timestamp-format query params; per-request response {ingested, failed, failures, processedBytes}) plus OTLP/HTTP endpoints (/v1/logs, /v1/traces, /v1/metrics selected by x-axiom-dataset header) and a family of shippers (Vector 'axiom' sink, Fluent Bit/Fluentd plain HTTP output, Cloudflare worker, Lambda extension) that all reduce to gzip/zstd NDJSON with a _time field; (2) a schema-on-read data model where nested JSON is flattened to dot-notation fields (foo.bar), field types are inferred and 'extended' on conflict, _time (event time; defaults to receive time) and _sysTime (ingest time) are reserved, and hard limits exist (10,000 events/batch, 1 MB field, 200-byte field names, 256/1,024 fields per dataset, 100-level nesting) with 'map fields' as the escape hatch for high-cardinality attribute bags, and retention/trim/vacuum as the lifecycle controls; (3) APL, which the CEO describes as 'a super subset of Microsoft's KQL' - pipe-delimited tabular operators (where, extend, project*, summarize, count, take/limit, sort/order, top, distinct, parse, search, make-series, union, join, lookup, mv-expand, parse-kv, redact, sample, getschema), KQL string operators (==, =~, contains, has, hasprefix, startswith, endswith, matches regex, has_any, *_cs variants), bracket quoting ['field.sub'] for names with dots/dashes/spaces, and Axiom-only additions such as bin_auto(_time), ingestion_time(), spotlight(), phrases(), topk(), histogram(), search with fieldname:"value" and wildcard-to-operator mapping; (4) a Console UI with a Query tab that toggles between a visual Builder (dataset, where filters, visualization/summarize, group by, time range, sort/limit) and an APL Editor (with Cmd/Ctrl-K natural-language generation), an event timeline histogram with drag-to-zoom, results table with slide-out event details ('View in context', 'Copy JSON', 'Copy link to event'), a Stream tab for live tail with severity colour-coding, a Datasets tab with a flattened field list (String/Number/Boolean/Array/Virtual), quick charts, saved queries and query history, virtual fields (query-time APL expressions stored per dataset), dashboards composed of elements (Time series, Statistic, Table, Log stream, Note, Heatmap, Pie, Scatter, Gauge, Top list, Monitor list, Filter bar, Spacer) each defined as Builder-or-APL query + visualization, and a 'More' menu offering Add to dashboard / Create new monitor / Copy-Download results (JSON, CSV, TOON) / Copy link with relative or absolute time; (5) monitors of three kinds - threshold (APL ending in summarize, threshold + above/below[or equal], frequency and range in minutes, alert-on-no-data, notify-by-group), match (per-event notifications, restricted to where/extend/parse/project* operators, 10/min and 500/day cap) and anomaly - fanned out to notifiers (Email, Slack, PagerDuty, Opsgenie, Discord, Custom Webhook, Microsoft Teams). Architecturally Axiom is a proprietary columnar block store on object storage queried by ephemeral serverless workers with no local block cache and result caching in object storage; that piece is not replicable, but the ingest contract, flattened-field model, APL surface and the Console UX all map cleanly onto Go + DuckDB (Parquet on disk, MAP/dot-flattened columns, hive partitioning by day) + Rails + shadcn.

## Findings

- **Ingest: endpoint and auth** (verified): Ingest endpoint is `POST https://AXIOM_DOMAIN/v1/ingest/DATASET_NAME` with header `Authorization: Bearer API_TOKEN` (API tokens only; personal access tokens are unsupported). The legacy path is `POST https://api.axiom.co/v1/datasets/{dataset_name}/ingest` (still used by the Lambda extension and Cloudflare worker). — source: https://axiom.co/docs/restapi/ingest
- **Ingest: accepted formats and content types** (verified): Accepted bodies: JSON array of objects (`Content-Type: application/json`), NDJSON one object per line (`application/x-ndjson`, also `application/json` and `application/nd-json`), CSV (`text/csv`, first row = header, or `X-Axiom-CSV-Fields` header with comma-separated field names; `csv-delimiter` query param default `,`). Verbatim NDJSON example: `{"id":1,"name":"machala"}\n{"id":2,"name":"axiom"}\n{"timestamp":"2016-06-06T12:00:00+02:00","attributes":{"key1":"value1"}}`. Verbatim JSON example: `[{"time":"2025-01-12T00:00:00.000Z","data":{"key1":"value1"}},{"data":{"key3":"value3"},"labels":{"key4":"value4"}}]`. Verbatim CSV: `user, name\nfoo, bar`. — source: https://axiom.co/docs/restapi/endpoints/ingestToDataset
- **Ingest: timestamp handling** (verified): Query params: `timestamp-field` = "The name of the field to use as the timestamp"; `timestamp-format` = Go reference layout `Mon Jan 2 15:04:05 -0700 MST 2006`. "If not specified, the timestamp will be the time the event was received by Axiom." Axiom "accepts many date strings and timestamps without knowing the format in advance, including Unix Epoch, RFC3339, or ISO 8601". All stored events have `_time`; if the event has no `_time`, Axiom assigns ingest time. `_sysTime` is the ingest time and is reserved; a user field named `_sysTime` is renamed `_user_sysTime`. `ingestion_time()` in APL returns the ingest timestamp, e.g. `| extend delay = datetime_diff('second', ingestion_time(), _time)`. — source: https://axiom.co/docs/reference/field-restrictions
- **Ingest: response shape** (verified): HTTP 200 body: `{"ingested":2,"failed":0,"failures":[],"processedBytes":219}`; full schema fields `ingested` (uint64), `failed` (uint64), `failures` (array of {error: string, timestamp: date-time}), `processedBytes` (uint64), `blocksCreated` (uint32), `walLength` (uint32). Rejected data points still return HTTP 200 with partial-success info; 401 on bad token. Optional header `X-Axiom-Event-Labels`: "An optional JSON encoded object with additional labels to add to all events". — source: https://axiom.co/docs/restapi/endpoints/ingestIntoDataset
- **Ingest: compression** (likely): Shippers send compressed bodies to the same ingest path: Fluent Bit config uses `Compress gzip`, the Lambda extension "sends gzip-compressed NDJSON to the `/v1/datasets/DATASET_NAME/ingest` path", Vector >= v0.42.0 "automatically enables the `zstd` compression algorithm by default" (or `compression = "gzip"`), and the OTel collector examples use `compression: zstd`. So gzip and zstd `Content-Encoding` are accepted on ingest, although the REST reference page itself does not enumerate Content-Encoding values. — source: https://axiom.co/docs/send-data/fluent-bit
- **Ingest: batch and size limits** (verified): System-wide limits: "Maximum events in a batch: 10,000"; "Maximum field size: 1 MB"; "Maximum field name length: 200 bytes"; maps/slices nesting deeper than 100 levels are truncated; oversized strings replaced with `<invalid string: too long>`; NaN/±Infinity become nil. Metrics-only: max request 4 MiB, metric name 256 bytes, attribute value 1 KiB, 256 histogram buckets. — source: https://axiom.co/docs/reference/limits
- **Ingest: OTLP endpoints** (verified): OTLP/HTTP endpoints: `https://AXIOM_DOMAIN/v1/traces`, `/v1/logs`, `/v1/metrics`. Dataset is selected by header `x-axiom-dataset: DATASET_NAME` (logs/traces) or `x-axiom-metrics-dataset` (metrics). Verbatim collector config: `exporters:\n  otlphttp:\n    compression: zstd\n    endpoint: https://AXIOM_DOMAIN\n    headers:\n      authorization: Bearer API_TOKEN\n      x-axiom-dataset: DATASET_NAME`. "The `/v1/metrics` endpoint only supports the `application/x-protobuf` content type. JSON format isn't supported for metrics ingestion." gRPC is not mentioned on the page. — source: https://axiom.co/docs/send-data/opentelemetry
- **Ingest: OTel attribute mapping** (verified): "Attributes that follow semantic conventions are nested fields under the `attributes` field. For example, `attributes.http.method` or `attributes.http.url`." "Resource attributes that follow semantic conventions are nested fields under the `resource` field. For example, `resource.host.name`." "Custom attributes that don't match any semantic conventions are nested fields under the `attributes.custom` map field." For OTel logs the level is read from `severity`, `severityNumber`, `severityText`. — source: https://axiom.co/docs/reference/semantic-conventions
- **Ingest: Vector integration** (verified): Vector has a native sink: `[sinks.SINK_ID]\ntype = "axiom"\ninputs = ["VECTOR_SOURCE_ID"]\ntoken = "API_TOKEN"\ndataset = "DATASET_NAME"\nregion = "AXIOM_DOMAIN"`. Since Vector v0.42.0 the timestamp is sent as `_time` (older versions used `@timestamp`), compression defaults to zstd. — source: https://axiom.co/docs/send-data/vector
- **Ingest: Fluent Bit / Fluentd integration** (verified): Both use the generic HTTP output against the ingest path, no special plugin. Fluent Bit: `[OUTPUT]\n Name http\n Match *\n Host AXIOM_DOMAIN\n Port 443\n URI /v1/ingest/DATASET_NAME\n Header Authorization Bearer API_TOKEN\n Compress gzip\n Format json\n JSON_Date_Key _time\n JSON_Date_Format iso8601\n TLS On`. Fluentd: `@type http`, `endpoint https://AXIOM_DOMAIN/v1/ingest/DATASET_NAME`, `headers {"Authorization": "Bearer API_TOKEN"}`, `json_array false`, `<format>@type json</format>`, `<buffer>flush_interval 5s</buffer>`; an Elasticsearch-bulk-compatible path `/v1/ingest/DATASET_NAME/elastic` exists for the opensearch output plugin. — source: https://axiom.co/docs/send-data/fluentd
- **Ingest: Cloudflare Workers payload** (verified): The official worker POSTs NDJSON to `https://api.axiom.co/v1/datasets/{axiomDataset}/ingest` with `Content-Type: application/x-ndjson`, `Authorization: Bearer {axiomToken}`, flushing "every 10 seconds or every 1000 logs". Event shape: `{ _time: Date.now(), request: { url, headers, method, ...cf }, response: { duration, headers, status }, worker: { version, id, started } }`. The Cloudflare Logpush app creates Logpush jobs via the Cloudflare API for zone- and account-scoped datasets (HTTP requests, DNS, Worker Trace Events) and ships an auto-installed dashboard. — source: https://raw.githubusercontent.com/axiomhq/axiom-cloudflare-workers/main/src/worker.js
- **Ingest: AWS Lambda integration** (verified): Axiom Lambda Extension is a layer configured by env vars `AXIOM_TOKEN`, `AXIOM_DATASET` (and optional `AXIOM_URL`), sends gzip-compressed NDJSON to `/v1/datasets/DATASET_NAME/ingest`, stamps `axiom.awsLambdaExtensionVersion`, and severity is detected from `record.error`, `record.level`, `record.severity`, `type`. Docs recommend keeping CloudWatch on and using the Axiom CloudWatch Forwarder for durability. — source: https://axiom.co/docs/send-data/aws-lambda
- **Data model: datasets and schemaless ingest** (verified): "Dataset names are 1 to 128 characters in length. They only contain ASCII alphanumeric characters and the hyphen (`-`) character." Schema is defined on read: Axiom "continuously creates and updates the data structures during the data ingestion process". Type conflicts: "When you ingest an event where the value of an existing field has a new type, Axiom extends the field's type to support both the existing and the new type." Field name identifiers: 1-1024 chars, alphanumerics, `_`, space, dot, dash; case-sensitive. — source: https://axiom.co/docs/reference/datasets
- **Data model: flattening and field types** (verified): Nested objects are flattened into dot-notation field names by default: "the event `{"foo": { "bar": "baz" }}` appears as `foo.bar`", and `{"geo": {"city": "Paris"}}` creates a field named `geo.city`. Datasets tab field types are "String, Number, Boolean, Array, Virtual fields". Reserved names: `_time`, `_sysTime`, `_blockInfo`, `_cursor`, `_rowID`, `_source`; conflicting user fields are prefixed `_user_FIELDNAME`. — source: https://axiom.co/docs/query-data/datasets
- **Data model: field limits and map fields (high cardinality)** (verified): Fields per dataset: 256 (Personal), 1,024 soft limit (Axiom Cloud). "Map fields are a special type of field that can hold a collection of nested key-value pairs within a single field." Recommended when you "approach the dataset field limit", for unpredictable shapes (OpenTelemetry), feature flags or custom attributes. Trade-offs: "Querying map fields uses more query-hours than querying conventional fields" and they "don't compress as well as conventional fields". Created per dataset via Datasets > More > Create map field or the API. Access syntax: `['map_field']['property1']['property2']`, `map_field.property1.property2`, or mixed; note `['geo.city']` (flattened field literally named geo.city) is NOT the same as `['geo']['city']` (key inside a map field). — source: https://axiom.co/docs/apl/data-types/map-fields
- **Data model: retention, trim, vacuum** (verified): Retention: Personal plan 30 days; Cloud plan custom per dataset (any period incl. "Forever"); set via Settings > Datasets and views > Edit dataset retention. Trim: "Trimming permanently deletes data stored in blocks that are older than a date you specify" - Settings > Datasets and views > Trim dataset > pick date > type dataset name > Trim; asynchronous, may take several hours. Vacuum: "resets the number of fields associated with a dataset to the fields that occur in events within your retention period", no events deleted, "You can only vacuum fields once per day for each dataset". Datasets can be shared read-only with other orgs; delete requires typing the name. — source: https://axiom.co/docs/reference/datasets
- **APL: relationship to KQL** (verified): Axiom CEO: "So our query language APL it's a super subset of Microsoft's KQL, which is the Kusto Query Language." Axiom's official X account: "We're huge fans of @Azure Kusto's query language and modelled our own on it too". The docs themselves say only that APL is a pipe-delimited text language: "DatasetName | Operator ... | Operator ..." with datasets/fields quoted as `['name']` when they contain space, dot or dash or collide with keywords. — source: https://tractable.withorb.com/episodes/axiom-ceo-neil-jagdish-patel-no-more-sampling/transcript
- **APL: tabular operators supported** (verified): Official operator list: count, distinct, extend, extend-valid, externaldata, getschema, join, limit, lookup, make-series, mv-expand, order, parse, parse-kv, parse-where, project, project-away, project-keep, project-rename, project-reorder, redact, sample, search, sort, summarize, take, top, union, where. `union` supports wildcard datasets: `union withsource=dataset github*\n| summarize count() by dataset`. — source: https://axiom.co/docs/apl/tabular-operators/overview
- **APL: string operators** (verified): Operators (case-insensitive unless _cs): `==`, `!=` (case-sensitive), `=~`, `!~` (case-insensitive equals), `contains`, `!contains`, `contains_cs`, `!contains_cs`, `startswith[_cs]`, `endswith[_cs]`, `matches regex`, `!matches regex` (case-sensitive), `has`, `!has`, `has_cs`, `has_any`, `has_any_cs`, `hasprefix[_cs]`, `hassuffix[_cs]`, plus `in`/`!in`. "Unlike the `contains` operator, which matches any substring, the `has` operator looks for exact terms" (terms delimited by spaces, hyphens, underscores, dots). Example: `"North America" has "america"` is true. — source: https://axiom.co/docs/apl/scalar-operators/string-operators
- **APL: search operator (special-cased full text)** (verified): Syntax: `search [kind=CaseSensitivity] SearchPredicate` and `search [kind=...] [in (DatasetPattern)] SearchPredicate`; kind = default | case_insensitive | case_sensitive. Searches all fields unless restricted with `fieldname:"value"`. Wildcards map to operators: `axiom` -> has, `*axiom` -> hassuffix, `axiom*` -> hasprefix, `*axiom*` -> contains, `ax*ig` -> matches regex. Example: `['sample-http-logs']\n| search kind=case_sensitive "css"`. Docs warn non-field-specific search "has an impact on performance, especially when used over a high volume of events in a wide time range". — source: https://axiom.co/docs/apl/tabular-operators/search-operator
- **APL: summarize and aggregation functions** (verified): Syntax: `| summarize [[Field1 =] AggregationFunction [, ...]] [by [Field2 =] GroupExpression [, ...]]`. Aggregations: count, countif, dcount, dcountif, sum, sumif, avg, avgif, min, minif, max, maxif, percentile, percentileif, percentiles_array, percentiles_arrayif, histogram, histogramif, topk, topkif, make_list, make_list_if, make_set, make_set_if, arg_min, arg_max, stdev, stdevif, variance, varianceif, rate, spotlight ("Compares a selected set of events against a baseline and surface the most significant differences"), phrases ("Extracts and counts common phrases or word sequences from text fields"). Time binning: `| summarize count() by _time=bin(_time, 3h), repo` or `bin_auto(_time)`. — source: https://axiom.co/docs/apl/aggregation-function/statistical-functions
- **APL: bin_auto (Axiom-only)** (verified): `bin_auto(expression)` "Rounds datetime values down to a fixed-size bin with automatic size selection"; "The bin size is calculated based on the query's time range to provide an appropriate number of data points"; works with `_time` only. Examples: `['sample-http-logs']\n| summarize request_count = count() by bin_auto(_time)` and `['otel-demo-traces']\n| summarize span_count = count() by bin_auto(_time), ['service.name']\n| order by span_count desc`. Threshold monitors warn on bin_auto and ask for `bin`. — source: https://axiom.co/docs/apl/scalar-functions/rounding-functions/bin-auto
- **APL: datetime and timespan** (verified): Functions: now(), ago(timespan), datetime_part, datetime_add, datetime_diff, dayofmonth/dayofweek/dayofyear, getmonth/getyear, hourofday, monthofyear, week_of_year, startofday/endofday/startofweek/endofweek/startofmonth/endofmonth/startofyear/endofyear, unixtime_{seconds,milliseconds,microseconds,nanoseconds}_todatetime. Literals: `datetime(2019-11-30 23:59:59.9)`, timespans `1.5h`, `30m`, `10s`, `'2d'`, `timespan(15s)`. Scalar types: bool, datetime, dynamic, int/long (64-bit), real, string, timespan; `dynamic({"a":1, "b":{"a":2}})` and `dynamic([3, 4, "bye"])` literals. — source: https://axiom.co/docs/apl/data-types/scalar-data-types
- **APL: parse and make-series** (verified): parse: `| parse [kind=simple|regex|relaxed] Expression with [*] StringConstant FieldName [: FieldType] [*] ...`, e.g. `| parse uri with * 'duration=' req_duration_ms:int` and `| parse id with region '-' tenant '-' userId`; failed rows get null. make-series: `make-series [Aggregation [, ...]] [default = DefaultValue] on TimeField [in Range] step StepSize [by GroupingField [, ...]]`, e.g. `make-series count() on _time from ago(30m) to now() step 1m`, returning arrays for series_* functions. — source: https://axiom.co/docs/apl/tabular-operators/parse-operator
- **APL: string/JSON functions** (verified): parse_json ("Interprets a string as a JSON value and returns the value as dynamic"), todynamic, tostring, parse_csv, parse_url, extract, extract_all, replace_regex, split, strcat, trim, tolower, toupper, strlen, indexof, base64_encode_tostring, base64_decode_tostring, url_encode, url_decode, isempty, isnotempty, coalesce. Performance page: prefer map fields at ingest over `parse_json()` at query time; "Filter before parsing". — source: https://axiom.co/docs/apl/scalar-functions/string-functions
- **APL: example queries (verbatim)** (verified): `['sample-http-logs'] | summarize count() by bin_auto(_time)`; `['sample-http-logs'] | where method == "GET" and content_type == "application/octet-stream"`; `['sample-http-logs'] | project content_type, ['geo.country'], method`; `['sample-http-logs'] | take 100`; `['sample-http-logs'] | count`; `['github-push-event'] | summarize max_if = maxif(push_id, true) by size | top 10 by max_if desc`; `['sample-http-logs'] | distinct ['id'], is_tls`; `['sample-http-logs'] | where tostring(user_agent) matches regex "Mozilla/5.0"`; `['sample-http-logs'] | summarize Count = count() by server_datacenter | order by Count desc`; `['github-issue-comment-event'] | extend isBot = actor contains '-bot' or actor contains '[bot]' | where isBot == true | summarize count() by bin_auto(_time), actor`. — source: https://axiom.co/docs/apl/tutorial
- **APL: query API** (verified): `POST https://AXIOM_DOMAIN/v1/query/_apl?format=tabular` (or `format=legacy`) with JSON body `{"apl": "DATASET_NAME | limit 10", "startTime": "...", "endTime": "..."}`; response has `format`, `status` (elapsed time, rows examined, cursors), `tables` (fields + column-oriented data), `datasetNames`, `fieldsMetaMap`. — source: https://axiom.co/docs/restapi/query
- **APL: performance guidance** (verified): "Put the most selective filters first"; use `contains`/`contains_cs` rather than `matches regex`; "Use `search` for substring search" across all fields only when needed; "Use `project` or `project-keep`" early; "Always use `_time`" and `where _time >= ... and _time <= ...`; avoid `pack(*)` on wide datasets; keep dimensionality below "a few thousand" fields; standardize types since mixed-type fields "reduce compression". — source: https://axiom.co/docs/reference/performance
- **UI: Query tab - Builder vs Editor** (verified): Query tab has two modes chosen top-left: **Builder** ("Select the data you want to query" dataset picker; Filters/where with field, operator, value; Visualizations/summarize e.g. count over time; Group by e.g. geo.country; **More** for manual sort order and event limit; Time range button with Quick range items and natural-language dates like "1 hour ago"; **Run** button) and **Editor** (text editor auto-detecting APL or MPL; Cmd/Ctrl K generates a query from natural language with Accept / Accept and run / Reject). — source: https://axiom.co/docs/query-data/query-editor
- **UI: Builder visualization types** (verified): Builder visualizations: count, distinct, avg, max, min, sum, percentiles, histogram ("buckets the field into a distribution of N buckets, returning a time series heatmap chart"), topk, variance, stddev - each "produces a time series chart", with group-by producing one series per group; percentiles with group-by renders a horizontal bar chart. — source: https://axiom.co/docs/query-data/visualizations
- **UI: query results, histogram, event details** (verified): Results show an "event timeline" of event distribution; "drag the pointer over the chart" then choose **Zoom** or **Show events**. Charts can be area, bar or line with null-value handling, linear/log scale, annotations, merged charts, and a **Compare period** menu (dotted line). Raw APL results render as a table; with visualizations a totals table. Click an event to open details with **Navigate up/down**, **View in context**, **Copy link to event**, **Copy JSON**, null toggle. **Toggle fields panel** picks columns ("Single column for event" vs "Column for each field"). Cmd/Ctrl F searches results. — source: https://axiom.co/docs/query-data/query-results
- **UI: 'More' menu / Send to dashboard flow** (verified): Top-bar **More** menu: **Add to dashboard** ("lets you create dashboard elements based on the query and add them to a dashboard"), **Create new monitor** ("lets you create a monitor based on the query"), **Copy results** and **Download results** in "JSON, CSV, TOON (structured), or TOON (list)", **Copy link with relative time**, **Copy link with absolute time**. — source: https://axiom.co/docs/query-data/save-export-query
- **UI: Stream (live tail)** (verified): Stream tab "continuously checks for new events and presents them in the stream", with "a powerful filter builder right on the toolbar", a pause/return-to-live control, historical time ranges, click-to-open slide-out with field values / JSON / raw, view settings for text size, line wrap and shown fields, and automatic severity colouring (warnings orange, errors red) when a level field is configured. Saved queries accessible from the toolbar. — source: https://axiom.co/docs/query-data/stream
- **UI: Datasets tab, field sidebar, saved queries, history** (verified): Datasets tab shows the flattened field list on the left with types String/Number/Boolean/Array/Virtual; fields can be edited (description, unit for numbers, Hidden); "Quick charts allow fast charting of fields depending on their field type" (Percentiles, Averages, Histograms for numbers); right sidebar has **Views**, **Saved queries** (toggle mine vs organisation; "Saved queries are automatically visible to all members of your Axiom organization") and **Query history** (mine vs team). Schema can be locked. Top-values-per-field sidebar was not found in the docs pages read. — source: https://axiom.co/docs/query-data/datasets
- **UI: virtual fields** (verified): "Virtual fields allow you to derive new values from your data in real time"; "Virtual fields are query-time representations only. They don't create new data in storage." Created in Datasets > dataset > **Virtual fields** > **Add virtual field** with Name, Description, Expression (APL) and a Preview; usable in filters, visualizations and group-by; may reference earlier-defined virtual fields; not supported on metrics datasets; re-parsed on every query. — source: https://axiom.co/docs/query-data/virtual-fields
- **UI: dashboards** (verified): "Dashboards provide a single view into your data. They visualize collections of queries across multiple datasets in one place." Element types: Filter bar, Gauge, Heatmap, Log stream, Monitor list, Note, Pie chart, Scatter plot, Statistic, Table, Time series, Top list, Spacer. Flow: **Edit dashboard** > **Add element** > pick type > for charts choose **Builder** or **APL** > optional custom time range / Compare period > **Save** (element) > **Save** (dashboard); drag title bar to move, bottom-right corner to resize; dashboard-level time range with per-element override; access control per dashboard. — source: https://axiom.co/docs/dashboard-elements/overview
- **UI: dashboard filters** (verified): Filter bar supports **Search filters** (free text) and **Select filters** (one option from a list); each chart opts in by referencing the filter ID in its APL, e.g. `where isempty(country_filter) or ['geo.country'] == country_filter`; filters can depend on one another (city depends on country). — source: https://axiom.co/docs/query-data/filters
- **Monitors: types and notifiers** (verified): "A monitor is a background task that periodically runs a query that you define." Types: Threshold ("aggregate event data over time. When the results of the aggregation cross a threshold, Axiom sends you an alert"), Match ("filter for key events and send them to you"), Anomaly ("look for values that are unexpected based on the event history"). Notifiers: Email, Slack, PagerDuty, Opsgenie, Discord, Custom Webhook, Microsoft Teams. Limits: 3 monitors (Personal), 500 soft (Cloud). — source: https://axiom.co/docs/monitor-data/monitors
- **Monitors: threshold configuration** (verified): Fields: name, description, query via Builder or APL (APL "must end with a `summarize` operator"; bin_auto triggers a warning - "use `bin` rather than `bin_auto`"), **Threshold** ("any numeric value"), comparison "above", "above or equal", "below", "below or equal", **Frequency** ("positive integer number of minutes"), **Range** ("positive integer number of minutes"), **Alert on no data**, **Notify by group** ("At most one trigger notification is sent per monitor run"). State: "enters the alert state if any of the values returned for the group-by attributes cross the threshold, and remains in the alert state until none of the values returned cross the threshold"; notifications on enter and exit. Monitors can be edited, disabled, enabled, cloned, deleted. — source: https://axiom.co/docs/monitor-data/threshold-monitors
- **Monitors: match configuration** (verified): "Axiom sends a notification for each matching event." Allowed operators: where, extend, extend-valid, parse, parse-kv, project, project-away, project-keep, project-rename, project-reorder (no summarize). "A match monitor can send 10 notifications per minute and 500 notifications per day"; notification payload usually up to 0.1 MB; creation refused "if more than 500 events match your query within the past 24 hours". — source: https://axiom.co/docs/monitor-data/match-monitors
- **Architecture: storage and query** (verified): Ingest: regional edge proxies -> "All ingested data is durably written to a distributed write-ahead log before being processed" -> streaming parse/validate -> EventDB (events) or MetricsDB. EventDB uses a proprietary columnar block format: dictionary encoding for strings, numeric compression, bitmap compression for booleans; immutable blocks hold compressed columns, metadata, statistics, time indexes and schema. Claimed compression: 25-50% at ingest, 10-20x block-level, 2-5x more at compaction. Queries: APL compiled to an execution plan, "multiple workers can process different blocks in parallel", workers "download only the necessary column data from object storage"; "Query results are cached in object storage". Claimed "millions of events per second while maintaining sub-second query latency". — source: https://axiom.co/docs/platform-overview/architecture
- **Architecture: blocks and serverless (blog)** (verified): "Blocks are our base unit of data storage and querying - they group columns with the same number of values, each column being a different type"; "We use object storage as a big shared disk where our blocks live, and serverless functions for query execution"; "we currently have no local block cache - each serverless function always requests the columns it needs from its assigned blocks from object storage". `_time` uses frame-of-reference (delta from min) or dictionary encoding. CEO: "we call it the registry, but it's like a catalog essentially of where those blocks are"; "Everything is hot all the time." — source: https://axiom.co/blog/a-database-hacker-story
- **Plans and pricing-based limits** (verified): Personal: 25 GB storage, 500 GB/month loading, 10 GB-hours/month query compute, 3 datasets, 256 fields/dataset, 3 monitors, 30-day retention. Axiom Cloud: 100 GB storage, 1,000 GB/month, 100 GB-hours, 100 datasets, 1,024 fields/dataset, 500 monitors, 1,000 users (all soft), custom retention. Query compute is metered in GB-hours, i.e. billing is per query work, not per seat. — source: https://axiom.co/docs/reference/limits

## Design implications

- Ingest contract: mirror Axiom's shape almost verbatim in the Go EventStore - `POST /api/logs/:dataset` (or `/v1/ingest/:dataset` for shipper compatibility) accepting JSON array, NDJSON and CSV by Content-Type, gzip/zstd Content-Encoding, `timestamp-field`/`timestamp-format` query params, and returning `{ingested, failed, failures:[{error,timestamp}], processedBytes}` with HTTP 200 on partial failure. Keeping the exact path/headers lets Fluent Bit (`URI /v1/ingest/DATASET`, `JSON_Date_Key _time`), Fluentd (`@type http`), Vector (`http` sink with ndjson codec; the native `axiom` sink hard-codes Axiom's host) and the Cloudflare worker point at SolidTrace with a one-line change.
- Auth: Axiom uses one Bearer API token per org with dataset scoping; SolidTrace already resolves a Sentry public key to a project in auth/project.go. Reuse the same lookup for `Authorization: Bearer <key>` on the log ingest path so a project's existing DSN key doubles as its log token, and add per-project 'datasets' (Rails model, name rules `[A-Za-z0-9-]{1,128}`) as the routing key. Also close the existing no-auth gap on the read API before exposing a query endpoint.
- Timestamp semantics: adopt Axiom's `_time` (event time, defaults to receive time, parsed leniently from RFC3339/ISO8601/epoch) and `_sysTime` (ingest time) as reserved columns in DuckDB. This maps to the existing UUIDv7 key (ingest order) plus a `_time TIMESTAMPTZ` column used for hive partitioning by `event_date`; keep `_sysTime` so late-arriving data can be reasoned about (`ingestion_time()`).
- Schema-on-read in DuckDB: flatten nested JSON to dot-notation keys at ingest (Go), keep a per-dataset field registry in SQLite (name, inferred type, first/last seen, hidden, description, unit) and store the wide, sparse key set in a DuckDB `MAP(VARCHAR,VARCHAR)` / `JSON` column for unknown keys while promoting hot/typed fields to real columns (DuckDB `union_by_name=true` on Parquet already tolerates schema drift). Enforce Axiom-like limits (10,000 events per batch, 200-byte field names, 1 MB field values, 100-level nesting, ~1,024 fields per dataset) and implement 'map field' semantics for high-cardinality attribute bags rather than promoting every key to a column. DuckDB type widening on conflict can be approximated by storing conflicting values as VARCHAR and recording the union type in the registry (Axiom 'extends the field's type').
- Query language: implement an APL/KQL subset compiled to DuckDB SQL in Go. Minimum viable set from Axiom's list: `where`, `extend`, `project`, `project-away`, `project-keep`, `project-rename`, `summarize ... by bin(_time, 5m)` / `bin_auto(_time)`, `count`, `take`/`limit`, `sort`/`order by`, `top N by`, `distinct`, `search` (all-fields substring with `field:"value"` and wildcard-to-operator mapping), `parse` (simple + regex), `make-series`, `union`; string operators `==, !=, =~, !~, contains[_cs], !contains, has[_cs], has_any, hasprefix, hassuffix, startswith, endswith, matches regex, in`; scalar functions `ago(), now(), bin(), tolower/toupper, strcat, extract, parse_json/todynamic, isempty/isnotempty, coalesce, datetime_diff`; aggregations `count, countif, dcount (approx_count_distinct), sum, avg, min, max, percentile (quantile_cont), percentiles_array, topk, make_list, make_set, arg_min, arg_max, stdev, variance, rate, histogram`. Bracket quoting `['geo.country']` is required for dot-notation field names, so the parser must accept `['...']` identifiers and translate them to quoted DuckDB columns or `map_extract(attrs,'geo.country')`.
- bin_auto: replicate Axiom's behaviour server-side - the query API receives startTime/endTime and picks a bin width targeting roughly 60-150 buckets; expose the chosen width in the response `status` so the histogram UI can label it. Threshold monitors should reject/warn on bin_auto like Axiom and require explicit bin.
- Query API: expose `POST /api/:project_id/query/_apl` in Go taking `{apl, startTime, endTime}` and returning a tabular, column-oriented response `{status:{elapsedTime, rowsExamined, binWidth}, tables:[{name, fields:[{name,type}], columns:[[...]]}]}`; that shape feeds both the results grid and the Recharts/shadcn chart with no reshaping and is the same payload dashboards, monitors and 'copy link with absolute time' will reuse.
- Console UI (Inertia + shadcn): build a Query page with a top-left Builder | Editor toggle (Builder = dataset select, where-filter rows with field/operator/value, visualization select [count, distinct, avg, min, max, sum, percentiles, histogram, topk], group-by multi-select, More: order/limit; Editor = APL textarea with keyword autocomplete), a time-range popover with quick ranges plus natural-language input, an event-timeline histogram above results with drag-to-select -> Zoom / Show events, a results table with a fields panel toggle (single-column raw vs column-per-field), and an event details Sheet with View in context, Copy JSON, Copy link, Navigate up/down. A 'More' dropdown holds Add to dashboard, Create monitor, Copy/Download results (JSON/CSV), Copy link (relative/absolute time). Add a Stream page (live tail via polling the Go read API every 1-2 s, pause/resume, severity colouring from level/severity/severityText, filter builder in toolbar).
- Field sidebar: Axiom's Datasets tab lists flattened fields with type, description, unit and hidden flag, plus quick charts by type. In SolidTrace this is the SQLite field registry rendered by Rails; 'top values' for a field can be a lazy `summarize count() by field | top 10` call to Go, which also powers click-to-add-filter in the Builder.
- Virtual fields and saved queries: store both in Rails (per dataset: name, description, APL expression; per user/org: saved query with APL, time range, starred flag; query history rows). The Go APL compiler must accept a virtual-field map from Rails and inline expressions before compiling, in definition order (Axiom allows references to earlier virtual fields).
- Dashboards: model as Rails Dashboard has_many DashboardElements(type, title, query_mode builder|apl, apl, builder_json, time_range_override, compare_period, layout x/y/w/h). Element types to ship first: Time series, Statistic, Table, Log stream, Note; later Heatmap, Pie, Top list, Gauge, Monitor list, Filter bar (search/select filters that elements opt into via `where isempty(f) or field == f`). Rendering: page loads elements, each fires the same `/query/_apl` call with the dashboard's time range unless overridden; Recharts via the shadcn chart wrapper.
- Monitors: Solid Queue recurring job per monitor. Threshold monitor = APL ending in summarize (validate in Go), threshold numeric, comparison above/above-or-equal/below/below-or-equal, frequency and range in minutes, alert-on-no-data, notify-by-group, state machine open->alert->resolved with notify on both transitions and per-group tracking. Match monitor = filter-only APL (where/extend/parse/project*), evaluated over the events since last run, per-event notifications rate-limited (10/min, 500/day), creation blocked if >500 matches in the last 24 h. Notifiers reuse SolidTrace's existing notification system (email, Slack, webhook, PagerDuty/Opsgenie/Teams/Discord as webhooks). Skip anomaly monitors initially.
- OTLP: Axiom's OTLP/HTTP logs endpoint is just protobuf-over-HTTP with dataset chosen by header; adding `POST /v1/logs` in Go (otlp proto -> flatten body/severity/attributes.*/resource.* -> same pipeline) is cheap and gives SDK-level compatibility; metrics/traces can wait. Use Axiom's field conventions (attributes.http.method, resource.service.name, attributes.custom map) so dashboards built against Axiom docs port over.
- Retention/trim/vacuum map directly onto the existing daily Parquet archive: retention = delete hive partitions older than N days (per dataset, from Rails), trim = delete partitions before a date, vacuum = rebuild the field registry from partitions inside retention. DuckDB `read_parquet(..., hive_partitioning=true)` with partition pruning on `event_date` plus a `_time` min/max per Parquet row group is the local analogue of Axiom's block time index.
- What is NOT replicable and should not be attempted: object-storage-resident proprietary blocks queried by fleets of serverless workers with result caching in object storage, 'everything hot forever', and GB-hour metered query compute. SolidTrace is single-node DuckDB reading local Parquet; design for that by (a) partition pruning by time first, always injecting `_time` bounds; (b) projecting only referenced columns (DuckDB is columnar and Parquet column-pruned); (c) keeping events_hot small (day-level archive already exists) and adding a per-query timeout/row-cap like Axiom's `status`; (d) optionally a DuckDB result cache keyed by (apl, start, end, dataset version) in SQLite/Pebble for dashboards.
- Ordering of operators matters for DuckDB translation: compile the APL pipeline into nested CTEs (one per operator) so `where` before `summarize` prunes Parquet and `search` after `where` scans fewer rows - this mirrors Axiom's own performance guidance ('put the most selective filters first', 'filter before parsing').

## Open questions

- Exact bin_auto algorithm (target bucket count) is undocumented; need to pick a heuristic (e.g. ~100 buckets snapped to 1s/5s/10s/30s/1m/5m/15m/1h/6h/1d) and expose the chosen width in the query response.
- Axiom's docs do not spell out how OTLP log records (body, severity_number, trace_id/span_id) are named as fields; only that attributes go under `attributes.*`, resources under `resource.*`, custom under `attributes.custom`, and level is read from `severity`/`severityNumber`/`severityText`. Confirm by sending a sample to Axiom or reading the axiom-go OTel exporter before fixing SolidTrace's field names.
- Whether Axiom's ingest accepts `Content-Encoding: gzip` on the generic /v1/ingest path is inferred from shipper configs (Fluent Bit `Compress gzip`, Lambda extension, Vector zstd) rather than stated on the REST reference page; treat gzip+zstd as the target regardless.
- Axiom's UI has a field sidebar with 'top values'/quick filters in practice, but the docs pages read only describe the Datasets tab field list, quick charts and the query-results fields panel; decide independently how much of a per-field top-values panel SolidTrace needs.
- How Axiom's builder-to-APL round trip works (converting a Builder query to editable APL and back) is not documented; SolidTrace should decide whether Builder state is stored separately (builder_json) and compiled to APL one-way, which is simpler.
- Type-conflict semantics in DuckDB: Axiom 'extends' a field's type to the union; DuckDB union_by_name across Parquet files with differing column types may error rather than widen. Need to test whether to coerce all promoted columns to VARCHAR on conflict or keep conflicting keys inside the MAP column.
- APL surface for dynamic/JSON values: Axiom offers `dynamic`, `parse_json`, `mv-expand`, `make_list`, `series_*`; how much of the dynamic type to support in the first cut (DuckDB JSON extension covers extraction but arrays-of-series are extra work).
- Match-monitor rate limits (10/min, 500/day) and threshold 'notify by group' semantics are Axiom product choices; confirm which limits SolidTrace wants given self-hosting has no per-tenant cost pressure.
- Whether to also support the legacy `/v1/datasets/:name/ingest` path and the Elasticsearch-bulk-compatible `/v1/ingest/:name/elastic` path for shippers that hard-code them (Lambda extension, opensearch fluentd plugin).
