# Prior research: kql

> Extracted from workflow run `wf_25055e4a-726` (solidtrace-logs-discovery, 2026-09-13, Fable subagents). Reference only: claims were not re-verified and design implications were never decided.


## Summary

KQL is a case-sensitive, pipe-structured language (Source | op | op ...; statements separated by ';', let statements must precede the tabular statement; '//' line comments only). The official reference implementation is Microsoft's Kusto.Language (C#, Apache-2.0, hand-written parser combinators) which also ships as a Bridge.NET JavaScript build (@kusto/language-service-next 12.4.1, ~32 MB unpacked) consumed by @kusto/monaco-kusto 15.0.1 (MIT, ESM-only, peer monaco-editor ^0.55.0, web-worker based, schema via setSchema/setSchemaFromShowSchema). Microsoft also publishes ANTLR grammars (grammar/Kql.g4 + KqlTokens.g4) that document precedence: or < and < (==,!=,in,!in,has_any,between) < relational < additive < multiplicative < string operators (=~, has, contains, startswith, matches regex...) < unary/primary. There is no usable Go KQL parser: the only Go repo (CraftedSignal/kql-parser, AGPL-3.0, ANTLR4) only extracts conditions, and the other 'kql' Go libraries target Kibana's unrelated KQL; Rust has rust-kql (nom, partial, DataFusion); C# has kql-to-sql (official parser -> DuckDB/PGlite SQL, 70+ operators) and Kusto-Loco (in-memory engine); ClickHouse has an experimental C++ Kusto dialect; Axiom's APL is modelled on KQL but its parser is closed. The semantics that matter most for a faithful DuckDB transpiler are: string operators default to case-INsensitive except ==, !=, in, !in, matches regex and *_cs variants; 'has' is term-based (terms = maximal alphanumeric runs, so underscore splits terms and RE2 \b is not equivalent); null is 'sticky' and where treats null as false; string has no null (isempty covers both); dcount/percentile are estimates (HLL/T-Digest); summarize output naming is count_, sum_x, dcount_x, percentile_x_95, list_x, set_x, countif_, sumif_x; sort default is desc with nulls last (asc = nulls first); join default kind is innerunique; take gives no ordering guarantee; bin()==floor(). DuckDB (RE2 regex, time_bucket anchored at 2000-01-03 for sub-month widths, regexp_extract with name list -> STRUCT, arg_max(arg,val) with reversed argument order vs KQL, approx_count_distinct, approx_quantile via T-Digest, list/list(DISTINCT)/any_value, FILTER clause, unnest, QUALIFY, json ->/->> with '$."key with space"', map[key] -> NULL when missing) has a direct counterpart for every KQL-Lite construct. Recommended v1: hand-written Go lexer + Pratt parser for a KQL-Lite subset compiled to a chain of DuckDB subqueries (one per pipe stage) with a schema-tracking pass, parameterized literals, forced project/time predicates, and a lightweight CodeMirror-or-Monaco editor fed by server-side diagnostics from the same Go parser.

## Findings

- **Language core: query structure** (verified): A Kusto query is one or more statements separated by ';'. Three user statement kinds: tabular expression statement, let statement, set statement. Tabular statement syntax: Source | Operator1 | Operator2 | RenderInstruction. 'KQL is case-sensitive for everything – table names, table column names, operators, functions'. Keywords usable as identifiers by bracket-quoting: ['where'] or ["where"]. Management commands start with '.' and are not part of KQL query syntax. — source: https://learn.microsoft.com/en-us/kusto/query/
- **Language core: let statement** (verified): Syntax: let Name = Expression;  and  let Name = [view] ([Parameters]) { FunctionBody };  'Let statements must be followed by a semicolon. There can be no blank lines between let statements or between let statements and other query statements.' Name may be bracket-escaped (['some number']). 'The let statement binds a name to a calculation, not to the evaluated value' (re-evaluated per reference; use materialize()/toscalar()). Innermost let wins on shadowing. Scalar param types allowed: bool, string, long, datetime, timespan, real, dynamic. Tabular params: (T:(col:type,...)) or (T:(*)). — source: https://learn.microsoft.com/en-us/kusto/query/let-statement
- **Language core: identifiers** (verified): Identifiers are case-sensitive, 1–1024 chars, may contain letters, digits, underscore, and (with quoting) spaces, dots, dashes. Reference forms: entity (plain); ['entity-name'] or ["entity-name"] for special chars, keywords (['where']) and literal-like names (['1day']). Names starting/ending with '__' are reserved. Lexer rule from KqlTokens.g4: IDENTIFIER = ('$'|'_'|'a'..'z'|'A'..'Z') ('_'|'a'..'z'|'A'..'Z'|'0'..'9')*. — source: https://learn.microsoft.com/en-us/kusto/query/schema-entities/entity-names
- **Language core: comments & whitespace** (verified): Only line comments: '//' to end of line (KqlTokens.g4: '//' ~('\n'|'\r'|' '|' ')*). No block comments. Whitespace includes tabs, spaces, newlines and Unicode spaces (U+00A0, U+2000–U+200B, U+202F, U+205F, U+3000, U+FEFF). — source: https://raw.githubusercontent.com/microsoft/Kusto-Query-Language/master/grammar/KqlTokens.g4
- **Literals: strings** (verified): Double- or single-quoted; escape with backslash (\", \', \t, \n, \\, \uXXXX). Verbatim: @"..." / @'...' where backslash is literal and the enclosing quote is escaped by doubling (lexer: '@"' ('""' | ~('"'|'\r'|'\n'))* '"'). Multi-line: ```...``` (also ~~~ per lexer), supports raw newlines, no escapes. Obfuscated: h"..." / H'...' prefix. Adjacent string literals (separated only by whitespace/comments) are automatically concatenated: strlen("Hello"', '@"world!") == 13. — source: https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/string
- **Literals: timespan** (verified): Forms: 2d, 1.5h, 30m, 10s, 100ms, 10microsecond, 1tick (100ns), timespan(15 seconds), timespan(2) (=2 days), timespan(0.12:34:56.7) (d.hh:mm:ss.ms), timespan(null). 'Week is not a supported length of time' (no nw). Lexer also accepts hr, milli, micro, nano and long forms minutes/seconds/days/hours. timespan and time are equivalent (time(1d)). timespan/timespan -> real. — source: https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/timespan
- **Literals: datetime** (verified): datetime(2015-12-31 23:59:59.9), datetime(2015-12-31), datetime() (current time), datetime(null); also quoted form datetime('2007-04-07') appears in docs examples. Always UTC; 100ns tick precision; range 0001-01-01..9999-12-31. Supported literal formats: ISO 8601 (%Y-%m-%dT%H:%M:%s%z etc., strongly recommended), RFC 822, RFC 850, sortable. now() and ago() return the same instant across all uses in one statement. — source: https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/datetime
- **Literals: numeric/bool/null** (verified): Unsuffixed integers and 0x hex are long (64-bit): 12, 0xf, long(-1), long(null). int is 32-bit only via int(2)/int(null). Decimals and scientific notation are real: 1.0, 1e5, real(null), real(nan), real(+inf), real(-inf). bool: true/false, bool(true), bool(null); 'bool' and 'boolean' equivalent. Null literal for any scalar type T is T(null); 'The string data type doesn't support null values.' — source: https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/long
- **Literals: dynamic** (verified): dynamic([1, 2, "hello"]), dynamic({"a":1, "b":{"a":2}}), dynamic(4), dynamic(null); in query text dynamic literals may embed datetime()/timespan literals (not when parsing strings). Accessors: dict.key, dict["key"], dict['key'] (equivalent for constant keys), arr[0], arr[-1] / arr[(-1)] for last, dict[col] with column subscript, dict.['where'] for keyword keys. 'Accessing a sub-object of a dynamic value yields another dynamic value' — cast with tolong()/todouble()/todatetime()/totimespan()/tostring()/toguid()/toint()/tobool(). — source: https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/dynamic
- **Grammar: official ANTLR grammar and precedence** (verified): microsoft/Kusto-Query-Language ships grammar/Kql.g4 and grammar/KqlTokens.g4 (ANTLR4). Entry: query: Statements+=statement (';' Statements+=statement)* (';')? EOF. Expression chain: expression -> pipeExpression; unnamedExpression -> logicalOrExpression (OR) -> logicalAndExpression (AND) -> equalityExpression (==, <>, !=, IN, HAS_ANY, BETWEEN, star-equality) -> relationalExpression (<,>,<=,>=) -> additiveExpression (+,-) -> multiplicativeExpression (*,/,%) -> stringOperatorExpression (=~, !~, HAS, CONTAINS, LIKE, STARTSWITH, ENDSWITH, MATCHES_REGEX ...) -> invocation/functionCallOrPath -> primaryExpression. namedExpression: (Name=identifierOrExtendedKeywordOrEscapedName | NameList '(' ... ')') '=' unnamedExpression. Note: 'and' binds tighter than 'or' (docs: 'The logical and has higher precedence than the logical or'); there is no bare '!' prefix operator — negation is not(expr); '!' only appears fused in !=, !~, !has, !in, !contains, !between etc. — source: https://raw.githubusercontent.com/microsoft/Kusto-Query-Language/master/grammar/Kql.g4
- **Grammar: repository license and parser tech** (verified): microsoft/Kusto-Query-Language LICENSE is Apache License 2.0. Repo contains the C# parser + semantic analyzer (src/Kusto.Language, built with parser combinators under Parser/Combinators) and a translator generating JavaScript. NuGet package: Microsoft.Azure.Kusto.Language (12.4.0 latest on nuget.org per search). Issue #56 ('Grammar File', 2021) asked for an official grammar; the /grammar folder is the answer but the fetched page shows no maintainer statement on its completeness/authority. — source: https://raw.githubusercontent.com/microsoft/Kusto-Query-Language/master/LICENSE
- **Kusto.Language API** (verified): var code = KustoCode.Parse(query);  code.Syntax.GetDescendants<NameReference>(n => n.SimpleName == "a");  var globals = GlobalState.Default.WithDatabase(new DatabaseSymbol("db", new TableSymbol("T", "(a: real, b: real)")));  var code = KustoCode.ParseAndAnalyze(query, globals);  code.GetDiagnostics() (Parse => syntax only; ParseAndAnalyze => syntax + semantic; check Severity); SyntaxElement.WalkNodes(code.Syntax, n => ...); nodes expose ReferencedSymbol and ResultType after analysis. — source: https://learn.microsoft.com/en-us/kusto/api/netfx/kusto-language-parse-queries
- **Operator: where** (verified): T | where Predicate  ('where' and 'filter' are equivalent). 'All filtering functions return false when compared with null values' — rows whose predicate is null are dropped. Column wildcard supported: StormEvents | where * has "cow". Perf guidance: simple column-vs-constant comparisons first; now()/ago()/let scalars count as constants. — source: https://learn.microsoft.com/en-us/kusto/query/where-operator
- **Operator: extend / project / project-away / project-keep / project-rename** (verified): extend: T | extend [ColumnName | (ColumnName[, ...]) =] Expression [, ...] — existing columns named by extend are removed and re-appended with new values; unnamed expressions get an auto-generated name (docs do not specify the scheme). project: T | project [ColumnName | (ColumnName[,]) =] Expression [, ...] or T | project ColumnName [= Expression] — output column order = argument order; all other columns dropped. project-away: T | project-away ColumnNameOrPattern [, ...] with wildcards (project-away session*). project-keep: T | project-keep ColumnNameOrPattern [, ...] (wildcards; keeps original order). project-rename: T | project-rename NewColumnName = ExistingColumnName [, ...] (order preserved). — source: https://learn.microsoft.com/en-us/kusto/query/project-operator
- **Operator: count / take / limit** (verified): T | count -> single row, single column named 'Count' of type long. take NumberOfRows ('take' and 'limit' equivalent): 'There is no guarantee which records are returned, unless the source data is sorted'; Kusto applies default result limits even without take. — source: https://learn.microsoft.com/en-us/kusto/query/take-operator
- **Operator: sort / order / top** (verified): T | sort by column [asc | desc] [nulls first | nulls last] [, ...] ('sort' and 'order' equivalent). 'Default is desc, high to low. Default for asc is nulls first. Default for desc is nulls last.' Null and NaN always group together. top: T | top NumberOfRows by Expression [asc | desc] [nulls first | nulls last]; default desc; 'top 5 by name is equivalent to the expression sort by name | take 5'. — source: https://learn.microsoft.com/en-us/kusto/query/sort-operator
- **Operator: distinct** (verified): T | distinct ColumnName[, ColumnName2, ...]; 'supports providing an asterisk * as the group key to denote all columns'. Output is marked non-serialized. — source: https://learn.microsoft.com/en-us/kusto/query/distinct-operator
- **Operator: summarize** (verified): T | summarize [SummarizeParameters] [[Column =] Aggregation [, ...]] [by [Column =] GroupExpression [, ...]]. No 'by' => single row. Empty input: no by => one row of defaults; with by => zero rows. Defaults: count/countif/dcount/dcountif/count_distinct/sum/sumif/variance/stdev => 0; make_bag/make_list/make_set => []; others null. 'The automatic hourly bins for datetime columns are no longer supported. Use explicit binning instead. For example, summarize by bin(timestamp, 1h).' Default output names from examples: count() -> count_, count(x) -> count_x, sum(x) -> sum_x, avg(x) -> avg_x, min/max -> min_x/max_x, dcount(x) -> dcount_x, countif(p) -> countif_, sumif(x,p) -> sumif_x, percentile(x,55) -> percentile_x_55, make_list(x) -> list_x, make_set(x) -> set_x, take_any(x) -> x (deprecated any() -> any_x), arg_max(x,*) -> original column names, duplicate names get suffix 1 (set_y, set_y1). Hints: hint.shufflekey=<key>, hint.strategy=shuffle, hint.num_partitions (ignorable). — source: https://learn.microsoft.com/en-us/kusto/query/summarize-operator
- **Operator: search** (verified): [T |] search [kind=CaseSensitivity] [in (TableSources)] SearchPredicate. Term matching by wildcard placement: billg -> has; *billg -> hassuffix; billg* -> hasprefix; *billg* -> contains; bi*lg -> matches regex (search "Lab*PC" == where * matches regex @"\bLab.*PC\b"). Column forms: col:"err" (== where col has "err"), col=="err" (exact), col matches regex "...". Booleans combine: search "abc" and ("def" or "hij"). search * == where 0==0. kind=case_sensitive makes all string comparisons case-sensitive; default/case_insensitive are synonyms. Output always includes column $table. — source: https://learn.microsoft.com/en-us/kusto/query/search-operator
- **Operator: parse** (verified): T | parse [kind=kind [flags=regexFlags]] expression with [*] stringConstant columnName [: columnType] [*] , ... ; kind = simple (default, strict), regex, relaxed (non-matching typed columns become null instead of failing whole row). '*' skips junk; '*' can't follow a string-typed column. Regex mode translation: pattern '* <regex1> var1:string <regex2> var2:long' becomes '.*?<regex1>(.*?)<regex2>(\-\d+)' ('*' -> .*?, string -> .*?, long -> \-\d+). Flags: U ungreedy, m multiline, s dot-matches-newline, i case-insensitive. Example: | parse EventText with * "resourceName=" resourceName ", totalSlices=" totalSlices: long * "sliceNumber=" sliceNumber: long * ... ; failed parse => null columns. — source: https://learn.microsoft.com/en-us/kusto/query/parse-operator
- **Operator: mv-expand** (verified): T | mv-expand [kind=(bag|array)] [with_itemindex=IndexColumnName] ColumnName [to typeof(Typename)] [, ColumnName ...] [limit Rowlimit]  or  [Name=] ArrayExpression [to typeof(...)]. Default row limit 2147483647 (legacy mvexpand: 128). Null dynamic => one row with null; empty array/bag => zero rows. Multiple columns are zipped in parallel (padded with null); cartesian product requires two mv-expand steps. Property bags expand to single-entry bags by default (kind=bag) or to [key, value] arrays (kind=array). 'to typeof()' is cast-only (non-conforming elements become null); output columns are dynamic unless typed. — source: https://learn.microsoft.com/en-us/kusto/query/mv-expand-operator
- **Operator: union / join** (verified): union: [T |] union [kind=inner|outer] [withsource=ColumnName] [isfuzzy=true|false] Tables (comma list, parenthesized query expressions, or wildcard E*). Default kind=outer (all columns from any input; missing cells null; same-name different-type columns split into name_type). Columns matched by name. No ordering guarantee across legs. join: LeftTable | join [kind=JoinFlavor] [Hints] (RightTable) on Conditions; flavors innerunique (DEFAULT — 'Inner join with left side deduplication'), inner, leftouter, rightouter, fullouter, leftanti (aliases anti, leftantisemi), rightanti (rightantisemi), leftsemi, rightsemi. Conditions: on ColumnName (same name both sides) or on $left.A == $right.B; multiple with 'and' or commas. No cross join (use extend placeholder=1). Hints (hint.strategy=broadcast/shuffle, hint.shufflekey, hint.remote) don't change semantics. — source: https://learn.microsoft.com/en-us/kusto/query/join-operator
- **Operator: serialize / row_number / make-series / render** (verified): serialize [Name1=Expr1 [, ...]] marks row set as ordered for window functions; sort, top, range, getschema, top-hitters output serialized rows; count, distinct, join, mv-expand, summarize, make-series output non-serialized. row_number([StartingIndex [, Restart]]) starts at 1; e.g. | sort by a desc | extend rn=row_number(); partition restart: row_number(1, prev(Airport) != Airport). make-series: T | make-series [Column=] Aggregation [default=DefaultValue] [, ...] on AxisColumn [from start] [to end] step step [by ...] -> per group one row with dynamic arrays (values + axis), bins via bin_at(AxisColumn, step, start), gaps filled with default (0), end exclusive, arrays capped at 1,048,576 elements; kind=nonempty yields default rows on empty input. render: T | render visualization [with (propertyName=propertyValue [, ...])] must be last operator; only adds a 'Visualization' annotation; values: table, timechart, linechart, areachart, stackedareachart, barchart, columnchart, piechart, scatterchart, card, anomalychart, etc.; properties: xcolumn, ycolumns, series, title, xtitle, ytitle, kind=stacked|stacked100|unstacked, legend, ymin, ymax. — source: https://learn.microsoft.com/en-us/kusto/query/make-series-operator
- **String operators: full table and case-sensitivity** (verified): Case-sensitive: ==, !=, contains_cs, !contains_cs, endswith_cs, !endswith_cs, has_cs, !has_cs, hasprefix_cs, !hasprefix_cs, hassuffix_cs, !hassuffix_cs, in, !in, matches regex, startswith_cs, !startswith_cs. Case-INsensitive: =~, !~, contains, !contains, endswith, !endswith, has, !has, has_all, has_any, hasprefix, !hasprefix, hassuffix, !hassuffix, in~, !in~, startswith, !startswith. Examples: "FabriKam" contains "BRik" true; "North America" has "america" true; "North America" !has "amer" true; "abc" in ("123","345","abc"); "Abc" in~ (...,"abc"); "Fabrikam" matches regex "b.*k". 'Case-insensitive operators are currently supported only for ASCII-text.' in supports scalar lists, dynamic arrays (nested arrays flattened) and tabular expressions (up to 1,000,000 distinct values; >128 terms disables index optimization). — source: https://learn.microsoft.com/en-us/kusto/query/datatypes-string-operators
- **String operators: term semantics of has** (verified): 'By default, each string value is broken into maximal sequences of alphanumeric characters, and each of those sequences is made into a term.' Example string 'Kusto: ad67d136-c1db-4f9f-88ef-d94f3b6b0b5a;KustoExplorerQueryRun' has terms Kusto, KustoExplorerQueryRun, ad67d136, c1db, 4f9f, 88ef, d94f3b6b0b5a. Term index built for terms of 3+ chars; shorter terms or contains fall back to scanning. '"KustoExplorerQueryRun" has "Explorer" will return false while "KustoExplorerQueryRun" contains "Explorer" will return true'. has_any syntax: col has_any (v1, v2, ...) | (dynamic([...])) | ((tabular)) — up to 10,000 values. Implication: underscore is NOT alphanumeric, so 'foo_bar' has 'foo' is true; a regex using RE2 \b (which treats '_' as a word char) would wrongly return false — emit (^|[^0-9A-Za-z])term([^0-9A-Za-z]|$) instead. — source: https://learn.microsoft.com/en-us/kusto/query/datatypes-string-operators
- **Logical/numeric operators and null semantics** (verified): ==, !=, and, or; and > or precedence. bool(null) and true => false-ish (docs: 'null values are treated as false' in where; table: bool(null) and true = false; bool(null) or true = true). General rule: null is 'sticky' for binary operators (null + 10 => null) except == / != with one null side (false/true), and-with-false => false, or-with-true => true. int/long ops yield long (integer division truncates: 1/2 == 0); real involvement yields real. Modulo is always non-negative: -14 % 12 == 10. between: expr between (leftRange .. rightRange), inclusive; rightRange may be a timespan only when expr and leftRange are datetime: StartTime between (datetime(2007-07-27) .. 3d). — source: https://learn.microsoft.com/en-us/kusto/query/scalar-data-types/null-values
- **Datetime functions** (verified): ago(timespan) = now() - timespan (T | where Timestamp > ago(1h)); now([offset]) e.g. now(-2d); all now()/ago() in one statement see the same instant. bin(value, roundTo) 'Rounds values down to an integer multiple of a given bin size', 'The bin() and floor() functions are equivalent'; value: int/long/real/timespan/datetime; roundTo: int/long/real/timespan; null/negative bin size => null; examples bin(4.5,1)=4, bin(time(16d),7d)=14d, bin(datetime(1970-05-11 13:45:07),1d)=1970-05-11. bin_at(value, bin_size, fixed_point) aligns to explicit origin (bin_at(datetime(2017-05-17 10:20), 7d, datetime(2017-06-04)) => 2017-05-14). startofday(date [, offset]) (plus startofweek/month/year, endof*). format_datetime(date, format) specifiers: d dd f..fffffff F..FFFFFFF h hh H HH m mm M MM s ss y yy yyyy tt; delimiters space / - : , . _ [ ]. Arithmetic: datetime - datetime = timespan; datetime ± timespan; timespan ± timespan; timespan / timespan = real (1h/1s = 3600); number * timespan. — source: https://learn.microsoft.com/en-us/kusto/query/bin-function
- **Conversion & conditional functions** (verified): toint(): signed 32-bit, 'If the conversion is successful, the result is an integer. Otherwise, the result is null', decimals truncate (toint(2.3)=2). tolong/todouble(toreal)/todatetime/totimespan analogous. tobool/toboolean: tobool("true")==true, tobool(1)==true, tobool(123)==true, null on failure. tostring(): 'If value is null, the result is an empty string.' parse_json(json) (deprecated aliases parsejson, toobject, todynamic): dynamic passes through; valid JSON string parsed; invalid JSON string => dynamic holding the original string; nested JSON strings need tostring() before second parse_json. iff/iif(if, then, else) equivalent. case(predicate_1, then_1, [predicate_2, then_2, ...] else) — all then/else same type. coalesce(arg, ...) returns first non-null 'or non-empty for string', max 64 args. isempty(v): true for "" or null; isnotempty; isnull/isnotnull (strings can't be null, so prefer isempty). not(expr) reverses bool; not(null) => null. — source: https://learn.microsoft.com/en-us/kusto/query/toint-function
- **String/regex functions** (verified): extract(regex, captureGroup, source [, typeLiteral]): group 0 = whole match; null on no match or failed conversion; e.g. extract(@"-(\d{2})-", 1, DateString, typeof(int)). extract_all(regex, [captureGroups,] source): 1–16 groups; 1 group => flat dynamic array, >1 => array of arrays; captureGroups may mix indexes and names dynamic(['first',2,'last']); null on no match. split(source, delimiter [, requestedIndex]) => dynamic array (split("a__b","_") = ["a","","b"]; index form returns single-element array ["bbb"]). strcat(arg1, ..., argN) 1–64 args, non-strings force-converted; strcat_delim(delim, ...). tolower/toupper, strlen, substring, indexof, replace_string, replace_regex, trim, countof, url_decode exist. matches regex: case-sensitive, partial match, max 16 groups. — source: https://learn.microsoft.com/en-us/kusto/query/extract-function
- **Regex dialect** (likely): The Kusto regex page does not name an engine; the documented syntax (\b{start}, \b{end}, \<, \>, class set operations [a-y&&xyz], [0-9--4], [a-g~~b-h], flags i m s R U u x, named groups (?P<name>) and (?<name>), no lookaround/backreferences listed) corresponds to the Rust `regex` crate syntax, not classic RE2. Flags set inline as (?i) / (?flags:exp). DuckDB uses RE2 (verified separately), which shares the core (no lookaround, (?i), \d \w \b, named groups) but lacks class set operators and \b{start}; regexes containing those must be rejected or rewritten. — source: https://learn.microsoft.com/en-us/kusto/query/regex
- **Aggregation functions** (verified): dcount(expr [, accuracy]) is an HLL estimate ('trades accuracy for performance, and might return a result that varies between executions'); accuracy 0..4 => error 1.6/0.8/0.4/0.28/0.2 %, default 1; exact counts for small sets (≤1000 at level 1). count_distinct() is the exact version. percentile(expr, p) / percentiles(expr, p1, p2, ...) / percentiles_array(expr, ...) are T-Digest nearest-rank estimates, median error capped at 1%, output columns percentile_x_5, percentile_x_50, ... arg_max(ExprToMaximize, * | ExprToReturn [, ...]) returns the row that maximizes the first arg (deprecated argmax()); arg_min symmetric. take_any(expr [, ...]) / take_any(*) (deprecated any(), which adds any_ prefix) picks an arbitrary record, prefers non-null for a single column. make_list(expr [, maxSize]) (default/max 1048576; nulls ignored; order follows input only if sorted), make_set (distinct, unsorted), make_list_if/make_set_if/make_bag. countif(predicate), sumif(expr, predicate), avgif, minif, maxif, dcountif. ## Design implications

- Write the KQL parser in Go by hand (lexer + Pratt parser over the KQL-Lite subset) — there is no reusable Go Kusto parser (CraftedSignal/kql-parser is AGPL and extraction-only; gokql/kql-go are Kibana KQL). Generating a Go parser from Microsoft's Apache-2.0 Kql.g4 via the ANTLR Go target is possible but the grammar is hundreds of rules and would drag in the full language; a ~2k-line hand parser gives precise error messages and full control. Keep the AST as a serializable Go struct (JSON) so the shadcn query-builder UI and the text editor both produce/consume the same AST and Rails can persist it alongside the KQL text.
- Compile pipes to nested DuckDB subqueries: each operator becomes SELECT ... FROM (<previous>) AS s<N>, with a schema-tracking pass (column names + inferred types) that is required for '*', project-away/keep wildcards, search over all string columns, join column-collision suffixes, summarize default names (count_, sum_x, dcount_x, percentile_x_95, list_x, set_x, countif_, sumif_x) and extend's replace-then-append semantics. Emit every literal as a bound parameter ($1, $2...) and double-quote every identifier; never interpolate user text. Force-inject 'project_id = $p' and a bounded time predicate on timestamp (and a derived event_date hive predicate so read_parquet prunes partitions) on the source scan, and add a default LIMIT (e.g. 1000) when the query has no take/count/summarize.
- Implement KQL string semantics precisely: default operators are case-insensitive (contains -> contains(lower(col), lower($p)); =~ -> lower()=lower(); in~ -> lower(col) IN (lower(...))) while ==, !=, in, matches regex and *_cs are case-sensitive; 'has' is term-based over maximal alphanumeric runs — use regexp_matches with explicit (^|[^0-9A-Za-z]) ... ([^0-9A-Za-z]|$) boundaries (RE2's \b treats '_' as a word character and would be wrong); 'search "x"' expands to OR of has over message/attribute columns; Kusto regex syntax is Rust-regex-like whereas DuckDB is RE2 — validate patterns with Go's regexp (RE2 syntax) at transpile time and surface a diagnostic.
- Time handling: evaluate now() once in Go per query and inline it (KQL guarantees a single instant per statement; also makes monitors/alerts deterministic and replayable); ago(x) -> that instant minus interval; bin(ts, w) -> time_bucket(INTERVAL w, ts) for widths dividing a day (identical results), and for multi-day widths choose an explicit origin (bin_at semantics) and document it; between is inclusive; format_datetime needs a yyyy/MM/dd/HH/mm/ss/fff -> strftime token translator.
- Null/empty semantics: DuckDB WHERE also drops NULL predicates, matching KQL where; but KQL strings are never null — normalize at ingest (missing string attributes stored as '' or handled via coalesce) and map isempty(x) -> (x IS NULL OR x = ''), tostring -> coalesce(...,''), coalesce(strings) -> coalesce(nullif(a,''),...). Ensure toint/todouble/tobool -> TRY_CAST so failures yield NULL like KQL.
- Schemaless logs on DuckDB: store structured attributes as a JSON (or MAP) column and expose them in KQL as a dynamic bag (attributes.key, ['attributes']['k y']) transpiled to col->>'$.key' / '$."k y"' with TRY_CAST for typed comparisons; mv-expand -> unnest(from_json(col, '["json"]')) (special-case the null-dynamic => one null row rule); summarize by on JSON-extracted keys works but is a scan — consider materializing hot keys into real columns (the KQL best-practice 'materialize at ingestion') and a per-project field-catalog table (name, inferred type, last_seen) maintained by the Go ingester to drive editor completion and the query builder.
- Aggregations: dcount -> approx_count_distinct (both estimates), count_distinct -> count(DISTINCT), percentile(x,p) -> approx_quantile(x, p/100) (both T-Digest) or quantile_disc for exactness, arg_max(ts, *) -> arg_max(struct_pack(...), ts) or one arg_max(col, ts) per surviving column (argument order is reversed in DuckDB), take_any -> any_value, make_list -> list(x) FILTER (WHERE x IS NOT NULL), make_set -> list(DISTINCT x), countif/sumif -> countif(p) / sum(x) FILTER (WHERE p); sort defaults desc + nulls last (asc => nulls first) must be emitted explicitly; join default innerunique needs a left-side dedupe subquery (QUALIFY row_number() OVER (PARTITION BY key) = 1).
- Editor choice for the Rails/Inertia/React 19/shadcn console: @kusto/monaco-kusto gives schema-aware IntelliSense and semantic validation out of the box but costs Monaco (peer ^0.55.0) + a ~32 MB unpacked language-service bundle, requires a dedicated 'kusto' web worker configured in Vite, and validates against full KQL (it would accept operators KQL-Lite rejects). Recommended: a lighter CodeMirror 6 editor (no off-the-shelf KQL mode exists — write a small StreamLanguage tokenizer for keywords/operators/strings/timespans and a completion source fed by the field catalog), with diagnostics from a Go endpoint (POST /api/:project_id/query/validate returning {errors:[{offset,length,message}], sql, columns}) produced by the same parser — one source of truth for what the language accepts. Keep monaco-kusto as a later upgrade path if users demand full IntelliSense.
- Product surface mapping: 'render <chart> with (...)' is parsed and returned as visualization metadata (not SQL) so the explorer/dashboard widgets can auto-pick chart type; saved queries, dashboard panels and monitors are stored in Rails (SQLite) as KQL text + AST + resolved time range, and executed by Go (Rails -> EventStore over the existing rest-client HTTP path, or via the console_messages outbox for scheduled monitors) with the read API now requiring auth (currently missing).
- Compatibility target: aim for Axiom-APL-compatible spelling (['field.name'] quoting, _time as the canonical time column, same operator set) since APL is modelled on KQL and users of Axiom/Sentinel will paste queries; document divergences (no evaluate plugins, no cluster()/database(), no functions in let) with explicit parser diagnostics rather than silent acceptance.
